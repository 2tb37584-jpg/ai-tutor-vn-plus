# M09-10 — Prevent Single-Symbol Leakage False Positives

Status: READY
Codex: YES

## Goal

Harden the deterministic answer-leakage guard so an expected answer consisting of a single symbolic variable such as `x` is not treated as leaked merely because the tutor mentions that variable in a Socratic prompt.

This is a runtime safety/UX correction, not an eval-only workaround.

## Evidence from M09-08

For:

`Thu gọn 2x + 5 - x - 5.`

the expected answer is `x`.

The live first turn was Socratic and did not state the result, but the detector returned `true` because the current non-numeric branch matches any standalone occurrence of the normalized expected answer.

A safe prompt such as “những hạng tử nào ... có thể gom lại” necessarily contains `x` when the original expression is mentioned.

## Module / micro-task

Module: deterministic answer leakage guard.

Micro-task:

1. distinguish single-symbol answers from larger symbolic expressions;
2. keep direct disclosures blocked;
3. allow instructional/reference use of the variable itself;
4. preserve `model_reports_reveal=True` as an unconditional leak;
5. add runtime-guard regression coverage.

## Required behavior

For expected answer `x`:

Safe examples must NOT leak:

- `Hãy gom các hạng tử chứa x.`
- `Trong 2x + 5 - x - 5, những hạng tử nào cùng loại?`

Direct disclosures must still leak:

- `Đáp án là x.`
- `Kết quả là x.`
- `x`
- any message with `model_reports_reveal=True`

Keep existing numeric-scalar protections unchanged.

Do not weaken detection for larger symbolic final answers unless a failing regression proves it is necessary.

## Acceptance criteria

- safe variable references no longer trigger;
- direct single-symbol answer disclosures still trigger;
- all existing leakage tests pass;
- API guard preserves safe TutorTurn content instead of replacing it with fallback for the new safe cases;
- true leaks are still replaced by the safe fallback;
- no dependency changes;
- full backend tests pass;
- `git diff --check` passes.
