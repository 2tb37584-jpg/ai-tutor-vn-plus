# M09-32 — Add deterministic pilot assessment domain service

Status: ACTIVE
Codex: Yes
Module: Evals
Phase: Phase 3 pilot readiness

## Goal

Provide the internal deterministic PRE/POST assessment service for persisted M09-30 frozen assignments. Use trusted authored question-bank lookup and deterministic verification only; add no public API.

## Deterministic authority

Persisted `PilotSkillAssignment` rows are the sole role authority. PRE uses `pre_question_id`; POST uses `post_question_id`; learning IDs are never assessment content. Verification uses `verification_request_for_candidate(...)` followed by `verify(...)`. No LLM, tutor, mastery, chat, hint, or learner-provided correctness signal is authoritative.

## Safe item and submission contracts

Expose internally only frozen dataclasses containing phase, question ID, skill code, problem text, and difficulty; and verification status, accepted, phase completion, and enrollment phase. Never include answers, references, verifier family, raw candidates, assignment IDs, or persistence metadata in the safe item.

Current-item lookup is deterministic by persisted assignment order. PRE selects the first incomplete PRE role. POST requires persisted `post` phase plus complete PRE and learning prerequisites, then selects the first incomplete POST role. Intervention and complete expose no item. Missing or mismatched authored questions fail closed.

Submission accepts the exact current question ID and caller-supplied `now`, flushes but never commits, and never persists the candidate. Correct/incorrect persist status plus timestamp and advance; unsupported/indeterminate persist status only and leave the same item current. Final PRE transitions only to intervention; final POST transitions to complete. M09-32 never transitions intervention to post.
