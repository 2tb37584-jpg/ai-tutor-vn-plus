# M09-40B — Harden chat-completions structured parsing for fenced JSON

Status: ACTIVE
Codex: Yes, small
Module: Tutor Engine
Phase: Phase 3 pilot operational readiness

## Goal

Make the `chat_completions` structured-output path tolerate valid JSON wrapped in one outer Markdown JSON code fence while preserving strict Pydantic validation and fail-closed behavior.

## Context

The mandatory synthetic browser dry-run failed during pilot learning because `/api/v1/tutor/reply` returned HTTP 500. An OpenAI-compatible chat-completions provider returned otherwise-valid structured JSON inside an outer Markdown code fence, and the SDK parse path attempted Pydantic JSON validation before application code could normalize the content. Phase 3 pilot GO is not granted. M09-41 and M09-42 remain BACKLOG. The separate short-`APP_SECRET` warning is outside this task.

## Micro-task

Keep the `responses` path unchanged. For `chat_completions`, make exactly one structured JSON-schema request, obtain raw assistant content, strip only an optional complete outer `json` or plain code fence and surrounding whitespace, then validate with the requested Pydantic model. Invalid, empty, prose-wrapped, or schema-invalid content must fail closed.
