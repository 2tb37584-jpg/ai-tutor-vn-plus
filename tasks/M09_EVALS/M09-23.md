## Pilot-ready coverage requirement

For the initial pilot, every assessed skill must have at least three distinct trusted authored question IDs:

```text
1 reserved for pre-test
1 reserved for measured learning exposure
1 reserved for post-test
```

The three-item rule is a protocol/content-readiness requirement, not a psychometric reliability or significance guarantee. Skills below three items remain in the target blueprint and are reported as coverage gaps; they are not silently dropped.

The minimum for equivalent pre/post forms alone is two distinct items per skill. Because the initial protocol also requires a distinct learning-exposure item, the pilot-ready requirement is three distinct items per skill.

## Pre / learning / post separation

The pre-test and post-test use the same locked skill blueprint and the same number of items per skill. For each learner and skill, the assigned pre, learning, and post question IDs must be distinct. All assigned items must be trusted authored items inside supported deterministic verifier families.

The reserved post-test item must not be shown to the learner before post-test. The learning-exposure item counts only as an exposure item and must not be reused as that learner's reserved pre or post item.

Form assignment must not rely on model prose or uncontrolled random selection. A future implementation must use a deterministic assignment rule or explicit deterministic seed. M09-23 defines the contract but does not implement assignment.

## Equivalent-form rules

Pre and post forms must:

- use the same locked nine-skill blueprint;
- contain equal per-skill representation;
- use distinct authored question IDs for the same learner across pre and post;
- use trusted authored items only;
- remain within supported deterministic verifier families;
- preserve deterministic scoring semantics;
- keep expected answers and verifier references server-internal.

Equivalent forms mean equivalent blueprint coverage and deterministic scoring semantics, not identical questions. No psychometric guarantee is implied.

## Assessment leakage boundary

Assessment-reserved items and learning-exposure items are separate roles. Assessment items must not be used as normal tutoring or recommendation items for the same learner during the measured intervention window.

At minimum:

- the learner must not receive the reserved post-test item during tutoring before post-test;
- reserved pre/post items must not be selected as ordinary learning items for that learner during the intervention;
- expected answers and verifier references remain server-internal and trusted only;
- learner-facing tutor responses and public payloads must not expose assessment answers or verifier metadata;
- recommendations must not disclose or reuse reserved assessment content.

## Intervention completion condition

The measured intervention is complete when the learner has completed at least one trusted authored learning item for every skill in the locked assessment blueprint during the intervention.

An item counts as completed only through the existing trusted tutor completion path. The learner is not required to answer it correctly. Completion does not depend on elapsed wall-clock time, number of chat messages, time spent, model judgment, or a mastery threshold.

This completion condition is the deterministic boundary between pre-test exposure and post-test eligibility. It does not change tutor state semantics, mastery rules, or recommendation policy.

## Pilot readiness gate

A full supported-domain Phase 3 pilot must not start until:

- every target skill has at least three distinct trusted authored items;
- distinct pre, learning, and post assignments can be made for every learner and skill;
- all assigned items remain inside supported deterministic verifier families;
- assessment leakage rules can be enforced;
- the intervention completion condition can be checked deterministically;
- M09-22 remains the cohort-measurement authority.

This is readiness for the defined protocol, not Phase 3 exit success. Actual pilot evidence and measured post-test improvement are still required for the roadmap exit.
