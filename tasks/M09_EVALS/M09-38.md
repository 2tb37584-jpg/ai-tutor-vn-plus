# M09-38 — Add aggregate pilot measurement report command

Status: ACTIVE
Codex: Yes, small
Module: Evals
Phase: Phase 3 pilot readiness

## Direction gate

Build one internal aggregate reporting seam from persisted pilot enrollment state. M09-37 remains the persisted-state projection authority, and M09-22 remains the measurement calculator authority. This task reports cohort evidence only; it does not decide Phase 3 exit.

## Goal

Add a read-only service and internal `python -m` command that projects all persisted pilot enrollments through M09-37, calculates the combined result through unchanged M09-22, and emits deterministic aggregate-only JSON to stdout.

## Context

The M09-22 pure paired calculator and M09-37 persisted assessment projection are complete. M09-38 composes them for an operational report without creating another measurement authority, exposing per-learner details, or persisting results.

## M09-22 authority

Reuse `PilotAssessmentRecord` and `calculate_pilot_measurement(...)` unchanged. Do not reimplement score calculation, paired matching, exclusion counting, or projection semantics.

## M09-37 authority

Reuse `project_pilot_assessment_records(...)` unchanged. M09-37 owns persisted-state projection and opaque pairing identity.

## Cohort selection

Select every persisted `PilotEnrollment` row, ordered by database ID. Do not filter by phase or add date, student, public-ID, or cohort filters. A never-started enrollment continues to project to no records and is not counted as both missing PRE and POST.

Read enrollment IDs and perform report reads under `db.no_autoflush`. Call projection exactly once per enrollment and the M09-22 calculator exactly once for the combined records.

## Aggregate-only output contract

Return a frozen internal aggregate result containing matched count; mean PRE, POST, and paired delta; median paired delta; improved, unchanged, and declined counts; and all five M09-22 exclusion counters. Do not expose learner identities, enrollment/assignment/question IDs, or skill codes. `mean_paired_delta` remains the primary measurement.

Do not invent a PASS/FAIL verdict, threshold, significance test, p-value, or effect-size gate.

## Command contract

Provide an internal command runnable from `backend` with `python -m app.services.pilot_measurement_report`. Use the existing `SessionLocal` and standard-library JSON serialization. Success prints exactly one deterministic JSON object and exits 0; `None` values are JSON null. No timestamps or random values.

On `PilotMeasurementProjectionError`, print only `Pilot measurement report unavailable` to stderr and exit 1. Unexpected programming/database failures are not converted to partial success. No additional CLI dependency or public API.

## Failure semantics

Any projection error aborts the entire report; never skip an enrollment or emit a partial cohort. Keep M09-37's no-state projection unchanged.

## Privacy boundary

Default output is aggregate-only. Never emit `public_id`, student identity or contact data, raw candidates/answers, question/verifier data, chat, or session content. Tests use synthetic data only.

## Read-only boundary

The service and command do not add, flush, commit, roll back, or mutate enrollment/assignment state. Closing the read session is allowed. Do not persist reports.
