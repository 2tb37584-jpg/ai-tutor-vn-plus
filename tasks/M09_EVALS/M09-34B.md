# M09-34B — Enforce active-pilot reserved-item guards across generic tutor paths

Status: ACTIVE
Codex: Yes, small
Module: Evals
Phase: Phase 3 pilot readiness

## Goal

Use persisted active-pilot assignment state to prevent generic tutor paths from exposing frozen PRE, LEARNING, or POST question IDs. Non-pilot behavior remains unchanged. This task does not implement pilot-specific learning-session start or provenance.

## Context and persisted authority

`PilotEnrollment` plus persisted `PilotSkillAssignment` rows are the only reservation authority. The resolver selects a non-terminal enrollment for the student and returns its persisted PRE, LEARNING, and POST IDs in stable assignment order. It never recomputes assignments, reads a seed, or trusts client data.

## Active-pilot definition

An active pilot is an enrollment for the student whose phase is not `complete`; `pre`, `intervention`, and `post` all count. No enrollment or completed-only enrollment returns empty exclusions. An impossible multiple-active or incomplete active assignment set fails closed with an internal state error.

## All-three-role reserved contract

For each assignment ordered by `PilotSkillAssignment.id`, reserve IDs in role order PRE, LEARNING, POST. All three roles are excluded from generic TRANSFER, generic post-completion recommendation, and direct `/tutor/start-authored`. No assignment recomputation or role inference is performed.

## Fail-closed state validation

The current blueprint requires exactly nine persisted assignments for an active enrollment. Missing, incomplete, unexpected, or multiple-active persisted state raises a narrow `PilotReservedQuestionStateError`. The tutor API maps only this error to `503 Tutor content is temporarily unavailable`; unexpected exceptions propagate.

## Generic guards

After student ownership is established, `/tutor/start-authored` rejects a reserved question with the existing non-disclosing `404 Question not found`, before session/message/AI/commit side effects. Generic TRANSFER selection receives the reserved tuple and never falls back to a reserved item. Generic completion recommendation forwards the same tuple; no eligible result remains a successful completion with no recommendation.

## Non-pilot compatibility

No-pilot and completed-only learners pass an empty exclusion tuple, preserving existing tutor response, state, verification, mastery, and recommendation behavior.

## M09-35 boundary

This task does not read or write `TutorSession.pilot_skill_assignment_id`, start exact assigned learning sessions, mark learning assignments complete, advance intervention, or implement pilot-specific TRANSFER behavior. Those decisions belong to M09-35/M09-36 and the later Workstream D trust review.

## Privacy and trust boundary

The resolver receives only `db` and `student_id`. It does not inspect names, email, phone, raw chat, candidate answers, LLM output, client reservation data, or assignment seeds. Frozen IDs never appear in public responses.
