## Approved architecture summary

- M09-30 owns the complete persistence foundation: a server-owned enrollment with opaque public pilot identity, student ownership/reference, lifecycle state, minimal lifecycle timestamps, and persisted per-skill assignment/result state sufficient for later assessment and intervention progression.
- Pilot enrollment creates a secure opaque random `assignment_seed`; the public identifier is persisted, while the seed is transient and discarded after assignment creation.
- The enrollment lifecycle must represent `PRE → INTERVENTION → POST → COMPLETE`; exact enum/string and column choices remain at the M09-30 database/schema checkpoint.
- Frozen assignments persist explicit PRE, learning, and POST IDs per skill and become the runtime authority; the seed is not persisted and runtime must not recompute assignments from question-bank order.
- Each frozen skill assignment reserves minimal trusted PRE result, learning completion, and POST result state without raw assessment-answer persistence.
- PRE and POST use a dedicated deterministic assessment path, not ordinary tutor sessions.
- Assessment correctness is deterministic; no LLM correctness judgment, hints, mastery update, answer feedback, expected-answer exposure, verifier-reference exposure, or unnecessary raw-answer persistence.
- Intervention enforces the exact persisted learning assignment, with a required nullable trusted reference from `TutorSession` to the persisted pilot skill assignment. Exact model/column naming is reserved for the M09-30 database/schema checkpoint.
- Active pilot sessions block all frozen PRE, learning, and POST IDs across generic next-learning recommendation, generic TRANSFER selection, and direct `/tutor/start-authored`; non-pilot behavior remains unchanged, and manually typed equivalent free text is outside this system-controlled leakage boundary.
- Inside the exact pilot-provenance learning session, TRANSFER blocks PRE and POST for that skill while the assigned learning item may remain eligible; before PRE completion, pilot learning start is unavailable, and after intervention POST is available only through the pilot assessment path.
- Intervention completes only after one exact assigned learning item is completed for each of the nine skills through the trusted tutor completion path.
- Persisted assessment state projects to `PilotAssessmentRecord`; M09-22 remains the calculation authority.
- Phase 3 requires synthetic validation, operational/privacy readiness, a real pilot, real paired pre/post evidence, and a final Phase exit review.
- A student may have at most one non-terminal pilot enrollment at a time; M09-31 rejects a new enrollment while one exists, without inventing reset or reenrollment semantics.
