# M09-09 — Constrain Problem-Analysis Skills to the Controlled Registry

Status: DONE
Codex: YES

## Goal

Make live `ProblemAnalysis.skills` generation obey the existing controlled Grade 8 skill taxonomy so the model does not invent free-form/synonym skill slugs.

This task addresses the M09-08 live-baseline finding that 86 of 87 skill-classification failures contained an `unknown` resolved skill.

## Evidence from M09-08

Representative model outputs included labels such as:

- `algebra.square_of_a_sum`
- `algebra.expansion`
- `algebra.binomial_square`
- `algebra.simplify_expression`
- `algebra.rational_expressions`
- `algebra.simplification`

The eval scorer correctly resolves unknown labels to `unknown`.

The current `ANALYZE_PROMPT` only asks for stable machine-readable slugs “where possible” and gives examples; it does not require selection from the controlled registry.

## Module / micro-task

Module: TutorAI diagnostic analysis / controlled skill registry.

Micro-task:

1. expose the controlled skill codes to the analysis prompt;
2. explicitly require returned `skills` to use only controlled codes;
3. require the smallest directly relevant skill set, preferring one primary skill when sufficient;
4. preserve all other `ProblemAnalysis` behavior;
5. add focused tests proving the request contract contains the controlled taxonomy.

## Allowed files

Modify only:

1. `backend/app/services/tutor_ai.py`
2. `backend/tests/test_tutor_ai_skill_contract.py` — new
3. optionally one directly relevant existing TutorAI test file if strictly necessary

Do not modify the registry data or eval fixtures in this task.

## Forbidden scope

Do not modify:

- `skill_registry.py` resolution rules;
- fuzzy matching;
- mastery logic;
- verifier;
- eval scoring;
- tutor-state transitions;
- answer leakage;
- provider transport;
- API schemas;
- frontend;
- dependencies.

Do not silently map arbitrary unknown labels to a “close enough” skill.

## Acceptance criteria

- analysis request includes the current controlled skill codes;
- model instruction says `skills` must use only codes from that list;
- no provider-specific logic is added;
- default/demo behavior remains unchanged;
- no free-form fallback alias is introduced;
- existing TutorAI tests pass;
- new contract tests pass;
- full backend tests pass;
- `git diff --check` passes.

## Tests

Add focused tests that verify:

1. every controlled code is present in the analysis request contract;
2. representative invented labels are not presented as allowed values;
3. existing analysis system instructions remain otherwise intact;
4. both `responses` and `chat_completions` modes receive equivalent controlled-skill instructions.
