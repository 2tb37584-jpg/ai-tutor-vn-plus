## Goal

Persist server-owned pilot enrollment, deterministic frozen PRE/learning/POST assignments, lifecycle state, minimal trusted assessment/progression state, and nullable TutorSession assignment provenance without persisting the assignment seed or raw assessment answers.

## Context

M09-24 remains the assignment authority. M09-29 requires this task to provide the complete persistence foundation needed by M09-32 and M09-36. The lifecycle is exactly:

```text
PRE → INTERVENTION → POST → COMPLETE
```

A student may have at most one non-terminal pilot enrollment. A completed enrollment may be followed by a later new enrollment; no reset or reenrollment semantics are added here.

## Approved schema

### PilotEnrollment

Add `pilot_enrollments` with integer `id`, unique non-null opaque server-generated `public_id` (`String(64)`), non-null indexed `student_id` referencing `students.id` with `ON DELETE CASCADE`, non-null `phase` (`String(32)`), and non-null `created_at`/`updated_at`.

The phase is constrained to exactly `pre`, `intervention`, `post`, or `complete`, using a named CHECK constraint rather than a database-native enum. Do not add cancelled, aborted, or reset phases.

### Single non-terminal enrollment invariant

Enforce at both service and database levels that a student has at most one enrollment where `phase <> 'complete'`. Use a named dialect-safe partial unique index such as `uq_pilot_enrollments_nonterminal_student` with PostgreSQL and SQLite predicates. Do not create unconditional uniqueness.

### PilotSkillAssignment

Add `pilot_skill_assignments` with integer `id`, indexed non-null `pilot_enrollment_id` referencing `pilot_enrollments.id` with `ON DELETE CASCADE`, non-null `skill_code` (`String(120)`), non-null `pre_question_id`, `learning_question_id`, and `post_question_id` (`String(120)`), plus nullable `pre_verification_status`, `pre_submitted_at`, `learning_completed_at`, `post_verification_status`, and `post_submitted_at`.

Require unique `(pilot_enrollment_id, skill_code)`, pairwise-distinct role IDs, and named CHECK constraints. Non-null statuses are limited to `correct`, `incorrect`, `unsupported`, and `indeterminate`. Question IDs are immutable question-bank identifiers, not database foreign keys.

Do not persist raw assessment answers, expected answers, verifier references, model prose, learner free text, or `assignment_seed`.

### TutorSession provenance

Add nullable `TutorSession.pilot_skill_assignment_id` as a foreign key to `pilot_skill_assignments.id` with `ON DELETE SET NULL` and a normal lookup index. This is server-trusted provenance and is not exposed or wired through public APIs in M09-30.

## Seed and enrollment service contract

Implement a small internal seam equivalent to:

```python
create_pilot_enrollment(db, *, student_id)
```

It must reject an existing non-terminal enrollment, generate separate secure opaque public ID and transient assignment seed values without using learner PII, call `assign_pilot_items(assignment_seed=assignment_seed)` exactly once, persist one `PilotEnrollment` in `pre`, persist every returned assignment, initialize result/completion fields to NULL, discard the seed, flush as needed, and never commit the caller's transaction. Do not log the seed. Focused tests may monkeypatch private generators.

## Timestamp rule

New timestamp defaults must use a non-deprecated naive UTC callable based on `datetime.now(UTC).replace(tzinfo=None)`. Do not refactor unrelated timestamp defaults.
