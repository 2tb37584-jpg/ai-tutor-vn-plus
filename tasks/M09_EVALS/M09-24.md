## Deterministic assignment contract

The later service must:

1. Reject an empty or non-string `assignment_seed`.
2. Use the locked nine-skill blueprint and its exact order.
3. Read authored items from the existing immutable question bank in declaration order.
4. Require at least three authored items for every skill.
5. For each `skill_code`, compute the offset exactly as follows:

   ```python
   payload = f"{assignment_seed}\x1f{skill_code}".encode("utf-8")
   digest = hashlib.sha256(payload).digest()
   offset = int.from_bytes(digest, byteorder="big", signed=False) % len(skill_questions)
   ```

   Here `\x1f` is the ASCII Unit Separator, the full 32-byte SHA-256 digest is used, integer conversion is unsigned big-endian, and the modulo is the number of authored questions for that skill.
6. Never use Python's built-in `hash()`.
7. Keep `skill_questions` in question-bank declaration order and select exactly:

   ```text
   pre      = skill_questions[offset]
   learning = skill_questions[(offset + 1) % len(skill_questions)]
   post     = skill_questions[(offset + 2) % len(skill_questions)]
   ```

   The role offsets are exactly `0`, `+1`, and `+2`, selected cyclically.
8. Ensure the three selected IDs for a skill are distinct.
9. Return assignments in locked blueprint order.
10. Return the same assignments for the same bank and seed.
11. Expose question IDs only, not answers, references, problem solutions, or verifier internals.
12. Avoid LLM calls, randomness, UUID generation, current time, database state, network calls, external I/O, platform-dependent encoding, and unordered collection iteration.
