## Goal

## Context

This projection adapts persisted role status/timestamps to that existing input contract without changing lifecycle, assessment, or calculator behavior.

Do not accept student identity, learner names, or raw answers. Output only the existing record fields: learner ID, phase, outcome, correct count, and valid scored count. Return PRE before POST when both records exist.

## Per-item persisted state mapping

Classify each phase independently from only its verification-status and submitted-at fields. Allowed statuses are `correct`, `incorrect`, `unsupported`, `indeterminate`, or `None`.

- Untouched: status `None` and timestamp `None`.
- Scored: status `correct` or `incorrect`, with a timestamp.
- Retryable unsupported/indeterminate: matching status and no timestamp.
- Every other pair—including unknown statuses—is invalid and makes that phase `invalid_incomplete`.

For exactly nine assignments, a valid phase requires all nine items scored. Its outcome is `valid`, numerator is the count of `correct`, and denominator is 9; incorrect items contribute only to the denominator.

An all-untouched phase is represented by absence of a record. A valid retryable prefix consists of zero or more scored items, exactly one unsupported or indeterminate item, then only untouched items. Project it to the corresponding exclusion outcome with both counts zero. All other partial, out-of-order, multiply retryable, or malformed patterns become `invalid_incomplete`, also with zero counts. Never guess or repair persisted state.

The blueprint has exactly nine assignments. An enrollment with any other assignment count projects both PRE and POST as `invalid_incomplete`, with zero counts; do not raise or infer a denominator from the observed count.

## Missing-phase semantics

Do not create a `missing` outcome. Absence of a PRE/POST record is M09-22's missing-phase representation. No state in either phase projects to `()`. A lone PRE or POST record lets M09-22 count the opposite phase as missing. Do not change M09-22 to count a never-started learner as both missing PRE and POST; that requires separate contract review.

## Read-only transaction boundary

Use `with db.no_autoflush:` around reads where appropriate. Projection must not add, flush, commit, rollback, or mutate enrollment or assignment objects. Missing enrollment raises `PilotMeasurementProjectionNotFound`; malformed pairing identity raises `PilotMeasurementProjectionStateError`. Ordinary exclusions and assignment-count mismatch are records, not exceptions. Unexpected database errors propagate.

## Privacy boundary

No verifier, LLM, question content, expected answer, verification reference, raw learner candidate, tutor session, mastery, or chat access. Repository tests use synthetic data only. No PII or internal database/assignment/question IDs may appear in returned records.
