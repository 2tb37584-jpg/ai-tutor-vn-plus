# M09-26 — Propagate reserved-question exclusions through next-learning-action adapter

Status: DONE
Codex: YES — SMALL
Module: Evals
Phase: Phase 3 pilot readiness

## Direction gate

This task advances Phase 3 pilot readiness by adding the smallest generic application seam that forwards caller-supplied reserved question IDs from `next_learning_action` to the deterministic recommender. It does not create assignments or claim the Phase 3 exit criterion.

## Goal

Allow caller-supplied exclusions to flow through:

```text
next_learning_action -> question_recommender(excluded_question_ids=...)
```

Do not implement assignment generation or runtime tutor/API wiring.

## Context

M09-24 is DONE and provides deterministic pilot item assignments. M09-25 is DONE and extends the recommender with:

```python
def recommend_next_question(
    *,
    mastery_snapshots: Iterable[MasterySnapshot],
    now: datetime,
    excluded_question_ids: Iterable[str] = (),
) -> QuestionBankItem:
    ...
```

The current adapter is:

```python
def recommend_next_learning_question(
    db: Session,
    *,
    student_id: int,
    tutor_state: TutorState,
    now: datetime,
) -> QuestionBankItem | None:
```

It currently calls the recommender without exclusions.

## Why now

The pure recommender can honor exclusions, but the existing learning-action adapter cannot yet carry caller-supplied exclusion context.

## Exit relationship

Completion means only that the next-learning-action adapter can forward caller-supplied reserved question IDs. It does not create pilot assignment context, wire M09-24 into tutor runtime, complete leakage enforcement, satisfy Phase 3, or authorize Phase 4.

Later implementation should extend the adapter equivalently to:

```python
recommend_next_question(
    mastery_snapshots=snapshots,
    now=now,
    excluded_question_ids=excluded_question_ids,
)
```

## Public contract

The adapter input is generic caller-supplied context. It must not know pilot semantics, generate assignment IDs, derive a seed, or use `student_id` as a seed.

## Forwarding semantics

If exclusions are omitted, existing callers behave exactly as before. For non-`COMPLETE` states, return `None` before DB flush, mastery queries, recommender calls, or consuming/validating the exclusions. On `COMPLETE`, preserve the existing flush, student-specific mastery query, snapshot mapping, single recommender call, unchanged forwarding, and unchanged selected-item return.

## Error ownership

The recommender remains the owner of exclusion validation and normalization. Invalid exclusion input on `COMPLETE` must propagate from the recommender. Preserve the existing special mapping of exactly `ValueError("no eligible question-bank skills")` to `None`; unrelated `ValueError`s must propagate.

## Architecture boundary

Do not import or call the M09-24 assignment service. Do not know pre/post role fields, derive assignment seeds, use learner identity as a seed, modify tutor API/runtime call sites, persistence, schemas, recommender logic, mastery behavior, or frontend.
