# M09-12 — Define Skill-Classification Eval Semantics

Status: ACTIVE
Codex: NO

## Goal

Define the correct evaluation semantics for `skill_classification` before rerunning the 100-case live baseline.

The current scorer uses exact set equality between expected and actual resolved skills. A 10-case post-fix live validation produced:

- 8 exact passes
- 2 exact failures
- 0 unknown skills

Both failures contained the expected controlled skill plus one additional controlled skill:

1. expected `algebra.identity.basic`
   actual `algebra.identity.basic` + `algebra.expression.distributive_property`

2. expected `algebra.rational_expression.simplify`
   actual `algebra.rational_expression.simplify` + `algebra.rational_expression.domain`

This task must determine whether those should be treated as:

- true classification failures;
- acceptable secondary-skill tagging;
- or a separate over-tagging diagnostic.

Do not change code until the evaluation contract is explicit.

## Why this task is next

Phase 1 exit requires the curated corpus to pass extraction/pedagogy regression checks.

Running another 100-case live baseline before defining skill-scoring semantics would spend provider credits while still producing ambiguous failures.

Product priority is weak-skill/misconception detection, so skill labels must be evaluated in a way that is both strict enough to prevent over-tagging and fair enough to allow genuinely relevant secondary skills.

`M09 Evaluation / skill classification metric`

## Questions this audit must answer

1. How many of the 100 corpus cases have:
   - exactly one expected skill;
   - more than one expected skill?

2. Is ordering of `ProblemAnalysis.skills` currently documented or relied upon anywhere?

3. Does any existing code treat `skills[0]` as a primary skill?

4. Would allowing arbitrary extra controlled skills let pathological over-tagging pass?

5. For the two observed live failures, are the additional skills pedagogically relevant or merely redundant?

6. Should the evaluator distinguish:
   - primary skill correctness;
   - unknown-skill violations;
   - controlled extra-skill over-tagging?

7. What exact metric contract should be used for the next 100-case live baseline?

## Preferred design direction to evaluate

A likely useful design is to separate concerns rather than turn exact-set equality into a broad subset check.

For example:

- unknown actual skill => fail;
- expected primary skill missing => fail;
- expected primary skill present => primary classification pass;
- extra controlled skills => record separately as `extra_skills` / over-tagging diagnostic;
- optional stricter rule for excessive extras.

This is only a hypothesis for the audit. Do not implement it unless the evidence supports it.
