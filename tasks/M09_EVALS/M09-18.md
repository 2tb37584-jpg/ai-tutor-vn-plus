# M09-18 — Refine Primary-Skill Specificity Precedence

Status: ACTIVE
Codex: YES

## Goal

Refine TutorAI's primary-skill ordering contract so that an explicitly targeted specific skill takes precedence over a broader umbrella skill, while preserving the successful M09-15 behavior.

This task addresses the systematic skill-classification regressions observed in the final Phase 1 100-case live regression.

## Context

The final M09-17 100-case live regression produced:

- answer leakage: 100/100 pass
- extraction correctness: 100/100 pass
- tutor state correctness: 100/100 pass
- verifier correctness: 8/8 scored pass
- unknown actual skills: 0
- skill classification: 89/100 pass, 11 fail

The 11 scored failures were systematic:

### 10 combine-like-terms cases

Expected primary:

```text
algebra.expression.combine_like_terms
```

Observed primary:

```text
algebra.expression.simplify
```

These are direct like-term collection tasks and do not require distribution or multiple transformation families.

### 1 identity case

Problem semantics:

```text
Use an algebraic identity to write a difference of squares as a product.
```

Expected primary:

```text
algebra.identity.basic
```

Observed primary:

```text
algebra.factorization
```

The explicit requested method is the identity, so `algebra.identity.basic` should remain primary and factorization may be supporting/secondary.

## Root cause

M09-15 correctly hardened the rule that a higher-level target skill should remain primary when prerequisite steps are involved.

However, the prompt now overgeneralizes `algebra.expression.simplify` as primary for direct simplification tasks, even when one more-specific controlled skill completely describes the learner objective.

The contract needs an explicit specificity-precedence rule:

- when one specific controlled skill fully describes the explicit learner objective, use that specific skill as primary;
- use a broader umbrella skill as primary only when the task genuinely requires coordination of multiple subskills or the broader skill is itself the explicit target;
- an explicit requested method can determine the primary pedagogical skill even when the mathematical output also belongs to another family.

## Required prompt semantics

The prompt must preserve all existing rules:

1. `skills[0]` is the single primary skill.
2. Primary represents the learner's main requested operation or pedagogical objective.
3. Supporting/prerequisite skills come after the primary.
4. Higher-level target skills remain primary when prerequisites are merely steps.
5. Rational-expression simplify/domain ordering remains intact.
6. Whole-expression simplify vs explicit distribution contrast remains intact.
7. Explicit identity expansion remains identity-primary.

Add the following generic specificity rule:

### Specific skill beats umbrella when sufficient

When one specific controlled skill completely describes the explicit learner objective, choose that skill as primary instead of a broader umbrella skill.

For example:

- a task that only collects like terms should use
  `algebra.expression.combine_like_terms`
  as primary, not `algebra.expression.simplify`;

- `algebra.expression.simplify` should be primary when the task genuinely coordinates multiple expression transformations, such as distribution plus combining like terms, or when broader simplification itself is the explicit objective.

### Explicit method can determine primary skill

When the learner is explicitly instructed to use a named method or concept, that requested method may be the primary pedagogical skill.

For example:

- when a task explicitly asks to use a basic algebraic identity to rewrite an expression as a product, use
  `algebra.identity.basic`
  as primary;
- `algebra.factorization` may be secondary if materially relevant.

Do not encode literal corpus text.
