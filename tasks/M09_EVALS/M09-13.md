# M09-13 — Align Skill Classification Eval with Primary-Skill Semantics

Status: ACTIVE
Codex: YES

## Goal

Align the `skill_classification` metric with the runtime semantics already used by AI Tutor VN:

- `analysis.skills[0]` is the primary skill;
- the Grade 8 eval corpus currently has exactly one expected skill per case;
- additional valid controlled skills may be secondary tags and should not automatically fail primary-skill classification;
- unknown skill labels must remain a failure.

This task changes eval semantics only. It must not change TutorAI generation, the skill registry, taxonomy data, mastery logic, or runtime primary-skill selection.

Read-only audit found:

- corpus case count: 100;
- all 100 cases have exactly one `expected_skills` entry;
- no multi-skill expected cases exist;
- runtime API uses `analysis.skills[0]` as `primary_skill`;
- current `score_skills()` converts expected and actual skills to sets;
- current scorer requires exact set equality;

## Metric contract

For the current Grade 8 corpus, `skill_classification` means **primary skill correctness**.

### Pass

Pass when all are true:

1. exactly one expected skill resolves to a controlled skill;
2. actual skills is non-empty;
3. the first actual skill resolves to the expected skill;
4. no actual skill resolves to `unknown`.

Additional controlled skills after the primary skill do not fail `skill_classification`.

They must be reported as diagnostics.

### Fail

Fail when any are true:

- expected skill resolves to `unknown`;
- actual skills is empty;
- first actual skill does not resolve to the expected skill;
- any actual skill resolves to `unknown`.

### Diagnostics

Return details sufficient to inspect over-tagging:

- `expected_primary`
- `actual_primary`
- `actual`
- `extra_skills`
- `unknown_actual_skill`

`extra_skills` should contain resolved controlled skills after the first actual skill.

Do not add a new top-level metric in this task.

Do not silently discard extra controlled skills from diagnostics.

## Why simple subset scoring is not acceptable

Do not implement:

```text
expected ⊆ actual
```

as the pass rule.

That would incorrectly pass:

```text
actual = [wrong_primary, expected_primary]
```

even though runtime uses the first skill as the session primary skill.

The first actual skill must match the expected primary skill.
