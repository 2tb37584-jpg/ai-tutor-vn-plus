# M09-25 — Add reserved-question exclusions to deterministic recommender

Status: DONE
Codex: YES — SMALL
Module: Evals
Phase: Phase 3 pilot readiness

## Direction gate

This task advances Phase 3 pilot readiness by adding the smallest pure recommender seam needed to exclude caller-supplied reserved question IDs. It does not wire pilot assignments into runtime or claim the Phase 3 exit criterion.

## Goal

Allow deterministic next-question selection to honor caller-supplied reserved question IDs while preserving all existing recommender policy and default behavior.

## Context

M09-24 is DONE and provides deterministic per-skill pilot assignments with `pre_question_id`, `learning_question_id`, and `post_question_id`. The pre/post IDs must eventually be protected from reuse during the measured learning intervention. The existing recommender considers the full immutable question bank and has no question-ID exclusion seam.

M09-25 adds only the pure exclusion capability. It must not wire pilot assignments into tutor, API, database, or recommendation orchestration.

## Why now

The deterministic pilot assignment seam exists, but reserved assessment questions cannot yet be excluded from ordinary next-question selection.

## Exit relationship

Completion means only that the pure recommender can honor caller-supplied reserved question IDs. It does not complete leakage enforcement, pilot readiness, Phase 3, measurable improvement, or authorize Phase 4.

## Micro-task

Later implementation is limited to the recommender and its focused tests. Extend the existing function equivalently to:

```python
def recommend_next_question(
    *,
    mastery_snapshots: Iterable[MasterySnapshot],
    now: datetime,
    excluded_question_ids: Iterable[str] = (),
) -> QuestionBankItem:
    ...
```

The default empty exclusions must preserve existing caller behavior.

## Public contract

`excluded_question_ids` is caller-supplied and is not pilot-specific inside the recommender. The recommender must not generate assignment IDs, know pre/post semantics, read pilot assignment state, or access database state.

## Validation semantics

Later implementation must:

1. Reject a direct string or bytes object used as `excluded_question_ids`.
2. Reject any excluded ID that is not a string.
3. Reject an empty-string excluded ID.
4. Normalize the iterable once into an immutable set-like value such as `frozenset`.
5. Allow duplicate IDs idempotently.
6. Allow unknown/nonexistent question IDs without changing selection.

Do not add question-bank existence validation for excluded IDs.

## Filtering-order invariant

Excluded questions must be removed before building `questions_by_skill` and before skill ranking:

```python
questions = tuple(
    question
    for question in get_all_questions()
    if question.id not in excluded_ids
)
```

Then build `questions_by_skill` from the filtered declaration-order sequence. A skill with all authored questions excluded must disappear from candidates so another eligible skill may be selected. If filtering and existing prerequisite eligibility leave no candidate skill, preserve the exact error `ValueError("no eligible question-bank skills")`.

For non-excluded items, preserve mastery snapshot validation, prerequisite eligibility, review scheduling, seen/unseen priority, mastery probability ordering, target difficulty, difficulty-distance selection, and declaration-order tie behavior.

## Architecture boundary

This task modifies only the pure deterministic recommender seam. It must not modify `next_learning_action.py`, tutor endpoints or state, pilot assignment, mastery, persistence, database/models, schemas/API, frontend, question-bank content, or dependencies.
