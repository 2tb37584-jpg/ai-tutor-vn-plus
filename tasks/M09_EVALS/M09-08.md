# M09-08 — Live Model Baseline Validation

Status: DONE
Codex: NO

## Goal

Validate the existing AI Tutor VN stack against a real configured model using the current canonical Grade 8 algebra corpus.

This task does not change tutor behavior or application code.

It establishes the first real-model baseline for:

- extraction correctness;
- skill classification;
- answer leakage;
- tutor-state correctness;
- deterministic verifier correctness.

## Context

Repository audit confirmed:

- Phase 1 implementation is complete through M09-07 and M10-02B;
- canonical Grade 8 algebra corpus contains 100 cases;
- the existing evaluation runner supports live mode;
- local `.env` exists;
- `OPENAI_API_KEY` is currently missing;
- without a key, `TutorAI` falls back to demo behavior;
- real analysis/first-turn evaluation has therefore not yet been proven.

The repository is the source of truth.

## Checkpoint C — one-case live smoke test

Do not spend a full 100-case run until one real live case succeeds.

Create a temporary one-case fixture outside the repository:

```powershell
$smokeCases = Join-Path $env:TEMP "ai-tutor-live-smoke.jsonl"

Get-Content .\evals\cases.jsonl -First 1 |
  Set-Content -Encoding utf8 $smokeCases
```

Copy it into the running backend:

```powershell
docker compose cp $smokeCases backend:/tmp/live-smoke.jsonl
```

Run the existing live evaluator:

```powershell
docker compose exec -T backend `
  python -m app.services.eval_runner `
  --mode live `
  --cases /tmp/live-smoke.jsonl
```

Acceptance for this checkpoint:

- command reaches the real configured model;
- JSON report is emitted;
- case is not reported as `live_execution_error`;
- extraction, skill classification, answer leakage, and tutor-state metrics are scored rather than `not_scored`;
- no secret appears in output.

If this checkpoint fails, stop and diagnose before running 100 cases.

## Checkpoint D — 100-case live baseline

Only after the one-case smoke succeeds:

```powershell
docker compose cp .\evals\cases.jsonl backend:/tmp/cases-live.jsonl
```

Save the complete machine-readable report outside the repository:

```powershell
$liveReport = Join-Path $env:TEMP "ai-tutor-live-baseline.json"

docker compose exec -T backend `
  python -m app.services.eval_runner `
  --mode live `
  --cases /tmp/cases-live.jsonl |
  Set-Content -Encoding utf8 $liveReport

Write-Host $liveReport
```

Do not commit this generated report.

## Checkpoint E — baseline summary

Read the JSON summary locally:

```powershell
$report = Get-Content $liveReport -Raw | ConvertFrom-Json

$report.summary | ConvertTo-Json -Depth 5
```

Also report:

```powershell
Write-Host "Case count:" $report.case_count
Write-Host "Mode:" $report.mode
```

Extract failing cases without dumping raw secrets or unnecessary model internals:

```powershell
$report.cases |
  ForEach-Object {
    $case = $_
    $failed = @(
      $case.metrics.PSObject.Properties |
      Where-Object { $_.Value.status -eq "fail" } |
      ForEach-Object { $_.Name }
    )

    if ($failed.Count -gt 0) {
      [PSCustomObject]@{
        id = $case.id
        failed_metrics = ($failed -join ", ")
      }
    }
  } |
  Format-Table -AutoSize
```

## Acceptance criteria

M09-08 is complete when:

- API key is configured locally without being exposed or committed;
- backend receives the configured environment;
- one-case live smoke succeeds;
- canonical 100-case corpus runs in live mode;
- report contains 100 cases;
- live metrics are actually scored;

- failing case IDs and failed metric names are identified;
- no application behavior is changed;
- no corpus case is edited;
- no generated report is committed;
- Git working tree remains clean except for task status files;
- concrete follow-up tasks can be derived from measured failures.

## Stop conditions

Stop before the 100-case run if:

- live smoke reports `live_execution_error`;
- credentials are rejected;
- provider/model configuration is invalid;
- model access is unavailable;
- eval runner output is malformed;
- the key would need to be exposed to debug the issue.

Stop after the 100-case run and create a separate task if fixing results would require production code changes.
