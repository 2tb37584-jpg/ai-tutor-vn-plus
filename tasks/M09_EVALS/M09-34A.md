# M09-34A — Add exclusion support to transfer-question selection

Status: ACTIVE
Codex: Yes, small
Module: Evals
Phase: Phase 3 pilot readiness

## Goal

Extend the deterministic `get_transfer_question_for_skill(...)` selector with optional caller-supplied question IDs that must not be selected. This task provides only a generic primitive; it adds no pilot-specific semantics.

## Context

The question bank already selects the first mastery-bearing item with a supported deterministic transfer family in declaration order. M09-34A adds an exclusion boundary while preserving that default behavior. M09-34B will later decide which persisted pilot IDs to exclude at runtime.

## Generic selector contract

The selector accepts `skill_code` and a keyword-only `excluded_question_ids` iterable defaulting to `()`. It normalizes exclusions once, then returns the first eligible non-excluded authored item in existing question-bank order, or `None` when no eligible item remains.

## Exclusion validation semantics

The exclusion iterable itself must not be `str` or `bytes`, and a non-iterable input raises `ValueError("excluded question IDs must be an iterable of strings")`. Every member must be a non-empty string; otherwise raise `ValueError("excluded question IDs must be non-empty strings")`. Unknown IDs, duplicate IDs, and IDs from another skill are harmless. The caller's iterable is not mutated.

## Default compatibility and deterministic ordering

Omitted exclusions and `excluded_question_ids=()` preserve the exact existing first eligible result. Exclusions only remove candidates; they do not alter transfer eligibility, ranking, declaration order, or introduce randomness, difficulty ranking, or mastery queries.

## Generic/pilot boundary

The selector knows only the skill code, exclusion IDs, normal transfer eligibility, and question-bank order. It does not receive or inspect students, enrollments, assignments, PRE/learning/POST roles, sessions, databases, or pilot provenance. M09-34B owns pilot runtime integration.
