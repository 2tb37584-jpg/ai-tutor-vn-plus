# M09-33 — Add trusted pilot PRE/POST delivery and submission API

Status: ACTIVE
Codex: Yes, small
Module: Evals
Phase: Phase 3 pilot readiness

## Goal

Expose the approved M09-32 deterministic assessment domain through exactly two owner-authorized HTTP routes. The API serves only the current persisted PRE/POST item and accepts a transient candidate for deterministic verification. It never exposes correctness, verifier metadata, expected answers, future reserved IDs, or raw learner answers.

## Context

M09-30 persists pilot enrollments and frozen role assignments. M09-31 provides owner authorization and status. M09-32 provides the deterministic current-item and submission domain service. M09-33 is the narrow public delivery boundary; it does not change assessment semantics or introduce persistence.

## Authorization boundary

Both routes use the existing `get_current_user`, resolve the path student, and require ownership before any enrollment lookup. Missing and non-owned students both return `404 Student not found`.

## Active-enrollment authority

Only `PilotEnrollment.student_id == student.id` with `phase != "complete"` is eligible. The client cannot provide a pilot or enrollment ID. Completed enrollments are never used for assessment delivery.

## Current-item delivery

`GET /api/v1/students/{student_id}/pilot/assessment` delegates to `get_current_pilot_assessment_item(...)` and returns only the current safe item. PRE exposes only the persisted PRE role; POST exposes only the persisted POST role. Intervention or no current item returns generic `409 Pilot assessment is not available in the current phase`.

## Transient submission

`POST /api/v1/students/{student_id}/pilot/assessment` accepts only `question_id` and bounded `candidate`, then delegates to M09-32 with server naive UTC time. The API commits every normal result, including retryable statuses, and never persists or logs the candidate.

## Identical no-correctness-feedback rule

Correct, incorrect, unsupported, and indeterminate normal outcomes all return exactly `204 No Content` with an empty body. No correctness, status, solution, hint, or explanation is returned. Unsupported and indeterminate remain retryable through M09-32.

## Error mapping

- question mismatch or unavailable item: `409` with a generic assessment message;
- state/configuration failure: `503 Pilot assessment is temporarily unavailable`;
- assessment not found after active lookup: `404 Pilot enrollment not found`;
- unexpected exceptions propagate to normal server handling.

All expected error paths roll back before returning where the request owns transaction state.

## Transaction boundary

M09-32 flushes but does not commit. The API owns `db.commit()` after every normal submission result and returns 204. It does not commit any other service operation.

## Privacy and leakage boundary

The public item contains exactly `phase`, `question_id`, `skill_code`, `problem_text`, and `difficulty`. It never exposes expected answers, verification references/families/status, assignment IDs, learning IDs, future IDs, raw candidates, or pilot internals. No tutor, LLM, mastery, attempt, message, or session side effects are allowed.
