# M09-31 — Add owner-authorized pilot enrollment/status API

Status: DONE
Codex: Yes
Module: Evals
Phase: Phase 3 pilot readiness

## Goal

Expose owner-authorized pilot enrollment and status operations for an owned student while keeping enrollment creation, assignment identity, lifecycle, and progress server-authoritative.

## API contract

Add only:

- `POST /api/v1/students/{student_id}/pilot`, with no request body, returning HTTP 201;
- `GET /api/v1/students/{student_id}/pilot`, returning the current non-terminal enrollment or most recent completed enrollment.

Both routes use the existing authentication dependency and return 404 `Student not found` for missing or non-owned students. POST reuses `create_pilot_enrollment(db, student_id=student.id)` and owns the commit. A duplicate active enrollment returns 409 with stable detail; only the known active-pilot database uniqueness conflict is mapped to 409, while unrelated integrity errors propagate.

## Authorization and response boundary

Only the authenticated owner of the path student may access these operations. The typed response exposes only `pilot_id`, `phase`, and persisted non-negative progress counts: `skills_total`, `pre_completed_skills`, `learning_completed_skills`, and `post_completed_skills`. Counts derive from the exact enrollment's assignments and submitted/completed timestamps.

Never accept or expose assignment seeds, question-role IDs, answer/verifier metadata, raw answers, assignment IDs, skill lists, or student PII. Do not infer progress from model output, mastery, chat count, or elapsed time.
