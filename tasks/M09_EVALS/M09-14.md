## Classification framework

Each residual failure must be assigned exactly one primary classification:

### A. Model variance

Use when:

- the same case produces different valid controlled primary ordering across runs;
- the fixture semantics are clear;
- no deterministic code defect is evident.

Typical follow-up:

- targeted rerun;
- prompt-contract hardening only if variance is systematic.

### B. Prompt / primary-skill ordering issue

Use when:

- the expected primary is clearly correct;
- the model consistently chooses a valid secondary skill first;
- runtime semantics depend on `skills[0]`.

Typical follow-up:

- small TutorAI prompt-contract task;
- add targeted prompt regression test.

### C. Ambiguous fixture / taxonomy semantics

Use when:

- more than one controlled skill can reasonably be considered the primary skill;
- the current expected primary is not clearly justified by the taxonomy;
- the case mixes multiple pedagogical operations.

Typical follow-up:

- taxonomy/fixture decision task;
- do not change scorer to hide ambiguity.

### D. Genuine extraction failure

Use when:

- `normalized_problem` adds/removes/duplicates numeric literals in a way that changes extraction fidelity;
- failure reproduces on targeted rerun or can be explained deterministically.

Typical follow-up:

- extraction prompt or scorer task, depending on evidence.
