## Dedicated-environment rationale

A dedicated pilot deployment and dedicated clean real-pilot database are mandatory. The synthetic browser dry-run normally uses a separate synthetic-only database that must never be reused for the real cohort. After the final dry-run, verify the intended real-pilot database contains zero pre-existing pilot enrollments, synthetic/test learners, and previous cohorts because M09-38 currently aggregates every persisted enrollment without cohort, date, or student filtering. If the intended pilot database is used for dry-run, require a reviewed complete datastore reset/recreation (not manual deletion of one enrollment row) and repeat clean-state verification after reset. If isolation or complete reset cannot be verified, the decision is NO-GO. Do not change M09-38 here.

## Consent/guardian boundary

Require adult participant consent, or both guardian consent and learner assent for minors, before account creation/enrollment. Consent records stay outside the application database and public Git in a private access-controlled location. Missing/uncertain consent means NO-GO for that participant. This is project policy, not a legal-compliance claim.

## Data minimization

Use pseudonymous display names where practical; no images or requests for personal/sensitive details during the measured pilot. TutorMessage free text is persisted, so participants must be told not to enter identifying or sensitive content. No real learner artifacts enter public Git.

## Retention/deletion policy

Learner-level data is retained only during the active pilot and while M09-42 review or incident resolution remains pending. After the M09-42 decision, delete it from the dedicated pilot environment as soon as operationally verified and no later than 30 calendar days. Withdrawal stops collection immediately and requires deletion as soon as verified and no later than 30 calendar days. If deletion cannot be safely performed, the pilot is not ready. M09-40 adds no deletion API.

## Synthetic dry-run gate

Require a complete synthetic browser dry-run on the exact reviewed release commit/build, relevant runtime configuration, and application code intended for the cohort, using a separate synthetic-only database. Never reuse that dry-run database for the real cohort. Exercise enrollment, every PRE item, all nine learning sessions, POST, COMPLETE, and synthetic aggregate reporting. After the final dry-run, verify the real-pilot database is independently clean; if it was used for dry-run, reset/recreate it completely and re-verify. Any remaining synthetic state or unverifiable reset means NO-GO. M09-40 defines this gate but does not execute or claim it passed.

## Incident/rollback policy

For privacy, trust, correctness-integrity, or cohort-contamination incidents, stop enrollment and pause the cohort; do not manually repair state/results or continue measurement. Synthetic/test pilot state found in the real-pilot database before first real enrollment means NO-GO. If found after enrollment begins, treat it as database cohort contamination: pause the cohort, do not run or continue measurement, and require ChatGPT readiness re-review. Resume only after reviewed fix, required regressions, a repeated full synthetic browser dry-run, verified real-database clean state, and ChatGPT readiness re-review. Ordinary failures may resume only from confirmed server-owned state.

## Measurement evidence boundary

M09-37 remains projection authority, M09-22 measurement authority, and M09-38 report authority. Preserve mean paired delta and denominator/exclusion semantics. Keep aggregate evidence private; maintain a private operational roster/count for authorized/enrolled, never-started, matched, and excluded counts without rewriting calculator output.

## Readiness authorization boundary
