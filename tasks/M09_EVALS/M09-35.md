# M09-35 — Add exact assigned pilot learning-session start

Status: ACTIVE
Codex: Yes, small
Module: Evals
Phase: Phase 3 pilot readiness

## Goal

Add a dedicated server-controlled start path for pilot intervention learning. The server selects the exact next incomplete persisted LEARNING assignment, resolves its trusted authored question, starts an authored tutor session, and persists exact assignment provenance.

## Context

M09-30 persists frozen pilot assignments. M09-32 provides deterministic PRE/POST assessment behavior. M09-34B prevents generic tutor paths from exposing any active pilot's frozen PRE, LEARNING, or POST items. M09-35 adds the narrow pilot-specific path that may start only the currently authorized LEARNING item without weakening those generic guards.

## Public API contract

Add exactly `POST /api/v1/tutor/start-pilot-learning/{student_id}` with no request body. The route reuses `StartAuthoredTutorResponse` and exposes only the learner-safe current question fields and first tutor turn.

## Persisted authority

The owned student, active persisted `PilotEnrollment`, and its persisted `PilotSkillAssignment` rows are the only authority. The client supplies no pilot ID, assignment ID, skill, question ID, assessment role, or seed. Assignment generation is never rerun.

## Phase gate

Only an active enrollment in `intervention` may start pilot learning. Missing or completed-only enrollment returns `404 Pilot enrollment not found`. Active PRE or POST returns `409 Pilot learning is not available in the current phase`.

## State validation

The active intervention must have exactly nine assignments ordered by persisted assignment ID. Every PRE result must be scored as `correct` or `incorrect` with a submission timestamp. POST state must remain untouched. Learning completion timestamps must form a completed prefix. Retryable PRE states, malformed cross-phase state, non-prefix completion, and all-complete intervention state fail closed.

## Exact assignment selection

Select the first persisted assignment whose `learning_completed_at` is null. Return its exact database assignment ID and exact persisted `learning_question_id`; do not use a recommender, fallback skill, neighboring item, or fuzzy lookup.

## Trusted question resolution

Resolve the persisted LEARNING ID with `get_question(...)`. The question must exist, its ID must match exactly, and its skill must equal the assignment skill. Missing or mismatched authored configuration fails closed.

## TutorSession provenance

The successful session stores the owned student ID, exact authored LEARNING question ID, exact `pilot_skill_assignment_id`, exact assignment skill, and a null initial `transfer_question_id`. Expected answers and verifier metadata remain server-internal.

## M09-34B interaction

The generic `/tutor/start-authored` route continues to reject the same frozen LEARNING item with non-disclosing `404 Question not found`. The pilot-specific route performs its own authority checks and calls a shared private authored-session constructor; it does not call the generic route or weaken its guard.

## Repeated-start boundary

While the current assignment remains incomplete, repeated pilot-start requests may create additional tutor sessions for the same exact assignment and question provenance. M09-35 does not invent active-session deduplication.

## M09-36 boundary

M09-35 does not write `learning_completed_at`, transition `intervention` to `post`, alter tutor completion semantics, enforce pilot-specific transfer behavior, or change mastery. M09-36 remains responsible for intervention completion and progression.

## Privacy/trust boundary

The response must not expose PRE or POST IDs, future LEARNING IDs, assignment or enrollment database IDs, expected answers, verification references/families, or assignment seeds. No raw learner answer or new personal data is persisted by this start path.
