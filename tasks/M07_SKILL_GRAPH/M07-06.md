# M07-06 — Complete Deterministic Transfer-Item Coverage

Status: ACTIVE
Codex: YES
Module: Skill Graph / Question Bank

## Goal

Make the authored Grade 8 algebra question bank provide at least one deterministic, prevalidated transfer item for every mastery-bearing skill.

This task is a prerequisite for deterministic tutor transfer completion.

Do not implement tutor runtime transfer behavior in this task.

## Context

M05-08 is DONE and established the deterministic transfer-completion contract.

The preferred transfer source is the existing immutable authored question bank because every `QuestionBankItem` carries, before the student answers:

```text
id
skill_code
problem_text
verification_reference
expected_answer
verification_family
difficulty
```

and question-bank loading already validates authored verification pairs through the existing deterministic verifier.

Current repository inspection found:

```text
mastery-bearing skills: 10
skills represented in question bank: 7
```

Known missing mastery-bearing skills:

```text
algebra.factorization
algebra.rational_expression.domain
algebra.rational_expression.simplify
```

The existing bank currently contains 12 authored items and uses supported verifier families:

```text
numeric
expression_equivalence
linear_equation
```

M05-08 also established that model-provided `likely_correct` is not acceptable transfer-completion evidence.

## Product decision for this task

Transfer-item coverage applies to **mastery-bearing controlled skills**.

`general.problem_solving` is a fallback/non-mastery skill and is not part of the authored deterministic transfer-item coverage guarantee.

Therefore:

- do not add a fake `general.problem_solving` question solely to satisfy coverage;
- do not invent a verifier family for `general.problem_solving`;
- question-bank coverage tests should quantify mastery-bearing skills only;
- runtime handling for a session whose skill is not transfer-eligible remains a Tutor Engine concern and is outside this task.

This resolves the question-bank side of the fallback contract without changing tutor-state semantics.

## Micro-task

Extend the authored question bank and its invariants so that:

```text
every mastery-bearing controlled skill
-> has at least one QuestionBankItem
-> whose verification_family matches the canonical skill definition
-> whose authored verification pair validates deterministically
```

Keep the task limited to authored data, question-bank invariants, and targeted tests.

## Canonical source of skill metadata

`backend/app/services/skill_registry.py` is read-only context for this task.

For each missing skill:

- read its canonical `verifier_family`;
- use that family exactly;
- do not infer or invent a different family;
- do not modify the registry.

If any missing skill's canonical verifier family is not already supported by the question bank/verifier, STOP and report instead of adding a new verifier family.

## Authored-item requirements

Add at least one deterministic authored item for each currently missing mastery-bearing skill:

```text
algebra.factorization
algebra.rational_expression.domain
algebra.rational_expression.simplify
```

Each new item must:

- use a unique stable ID following the existing ID convention;
- use the exact canonical `skill_code`;
- contain a student-facing `problem_text`;
- contain a deterministic `verification_reference`;
- contain an `expected_answer` that self-validates against that reference;
- use the canonical `verification_family` from the skill registry;
- use an authored difficulty in the existing allowed range `1..3`;
- not expose the expected answer inside `problem_text`;
- be suitable as an independent transfer/practice problem, not merely duplicate another item verbatim.

Do not add random or generated-at-runtime content.

## Question-bank invariant change

The existing loader currently assumes a fixed bank size and fixed family distribution.

That invariant must not block future authored coverage growth.

Replace fixed-count assumptions only as far as necessary to express the stronger product invariant:

```text
all mastery-bearing controlled skills are covered by >= 1 valid authored item
```

Preserve existing validation for:

- exact record fields;
- non-empty strings;
- difficulty type/range;
- unique question IDs;
- valid mastery-bearing skill codes;
- supported verification families;
- skill/family consistency;
- deterministic verification-pair self-validation.

Do not weaken those checks.

A fixed exact number of questions is no longer a useful invariant once coverage is the requirement.

Do not require equal counts per verification family unless there is a documented product reason already enforced elsewhere.
