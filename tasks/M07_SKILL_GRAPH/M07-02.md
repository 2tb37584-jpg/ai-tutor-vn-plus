# M07-02 — Controlled Skill Registry

Status: DONE
Codex: YES

## Goal

Implement the reviewed M07-01 taxonomy as a deterministic runtime registry.

The registry must expose only reviewed controlled skills.

Unknown or arbitrary LLM-generated labels must resolve to an explicit UNKNOWN outcome rather than silently creating curriculum skills.

## Context

M07-01 produced a reviewed Grade 8 algebra v1 taxonomy with 10 mastery-bearing skills.

The current canonical artifact is:

`docs/grade8_algebra_skill_taxonomy_v1.json`

However, the backend Docker build context is `./backend` and the development container mounts only:

`./backend:/app`

Therefore the root `docs/` directory is not available to the backend runtime.

M07-02 must correct this packaging boundary without maintaining two copies of the taxonomy.

## Packaging decision

Move the canonical taxonomy file from:

`docs/grade8_algebra_skill_taxonomy_v1.json`

to:

`backend/app/data/grade8_algebra_skill_taxonomy_v1.json`

The moved backend file becomes the single canonical taxonomy artifact.

Update the M07-01 documentation reference to point to the new canonical path.

Do not keep a duplicate JSON file under `docs/`.

The runtime registry must read the canonical JSON rather than duplicating the 10 skill records in Python source.

## Runtime contract

Create a deterministic registry service.

Recommended module:

`backend/app/services/skill_registry.py`

The registry must support:

- retrieving the controlled skill definitions;
- resolving a canonical skill code;
- resolving a reviewed alias;
- returning an explicit UNKNOWN outcome for unrecognized labels;
- distinguishing mastery-bearing controlled skills from UNKNOWN/reserved labels.

## UNKNOWN contract

Use one explicit runtime sentinel:

`unknown`

Recommended exported constant:

`UNKNOWN_SKILL_CODE = "unknown"`

Unknown labels must not:

- create a Skill row;
- become a new registry member;
- mutate the taxonomy;
- be treated as mastery-bearing;
- silently fall back to `general.problem_solving`.

`general.problem_solving` is a reserved non-mastery label and must resolve to UNKNOWN for controlled curriculum purposes.

M07-02 does not yet wire UNKNOWN into mastery persistence. It establishes the registry contract that downstream code must use.

## Label normalization

Alias/code lookup should be deterministic.

At minimum normalize:

- Unicode with NFKC;
- case with `casefold()`;
- repeated/leading/trailing whitespace.

Do not use fuzzy matching.

Do not guess the closest skill.

Do not automatically remove Vietnamese diacritics.

An input either resolves deterministically to one reviewed skill or returns UNKNOWN.

## Registry integrity

The loader should fail fast if the canonical data is invalid.

Validate at least:

- skill codes are unique;
- canonical codes are non-empty;
- aliases do not map to multiple skills;
- prerequisite codes exist;
- prerequisite graph is acyclic;
- reserved non-mastery labels are not mastery-bearing skills.

Do not add a new dependency for this validation.

## Module / micro-task

Module:

`M07 Curriculum / Skill Graph`

Micro-task:

Load the reviewed v1 JSON into a deterministic in-process controlled registry and provide exact code/alias normalization with explicit UNKNOWN handling.

## Allowed files

Implementation is limited to:

1. `docs/grade8_algebra_skill_taxonomy_v1.json` — remove as part of the move
2. `backend/app/data/grade8_algebra_skill_taxonomy_v1.json`
3. `backend/app/services/skill_registry.py`
4. `backend/tests/test_skill_registry.py`
5. `tasks/M07_SKILL_GRAPH/M07-01.md`

The existing JSON must be moved from `docs/` rather than copied.

After implementation, only the backend canonical JSON may remain.

No other application files should change.

## Forbidden scope

Do NOT modify:

- database models;
- Alembic migrations;
- TutorAI behavior;
- TutorState;
- tutor API;
- mastery update logic;
- verifier implementation;
- frontend;
- Docker Compose;
- Dockerfile;
- dependencies.

Do not seed the `skills` database table.

Do not perform fuzzy/semantic skill matching.

Do not add another taxonomy.

## Acceptance criteria

M07-02 is complete when:

- the canonical taxonomy exists only once in the repository;
- the canonical runtime JSON is under `backend/app/data/`;
- the registry loads exactly the 10 reviewed mastery-bearing skills;
- canonical codes resolve to themselves;
- reviewed aliases resolve to their intended canonical codes;
- normalization is deterministic;
- unknown labels resolve to `unknown`;
- `general.problem_solving` resolves to `unknown`;
- UNKNOWN is not mastery-bearing;
- repeated unknown lookups do not mutate the registry;
- prerequisites reference only controlled skills;
- invalid duplicate aliases/codes or cyclic/missing prerequisites fail validation;
- no application database or TutorAI behavior is changed;
- unit tests pass;
- full backend regression passes.

## Tests

Add `backend/tests/test_skill_registry.py`.

Cover at least:

1. registry loads exactly 10 controlled skills;
2. canonical code resolution;
3. Vietnamese alias resolution;
4. English alias resolution;
5. case/whitespace normalization;
6. Unicode NFKC normalization;
7. unknown label returns `UNKNOWN_SKILL_CODE`;
8. `general.problem_solving` returns UNKNOWN;
9. unknown lookup does not add a skill;
10. all prerequisites resolve to controlled skills;
11. malformed duplicate alias is rejected;
12. missing prerequisite is rejected;
13. prerequisite cycle is rejected.

After targeted tests pass, run the complete backend test suite.

## No new dependencies

Use Python standard library and existing project dependencies only.

A new dependency is not justified for this registry.

## Stop conditions

Stop and split the task if implementation requires:

- database migration;
- changing TutorAI prompts;
- changing mastery behavior;
- changing verifier behavior;
- modifying Docker packaging;
- expanding the taxonomy beyond the reviewed 10 skills.
