# M07-01 — Grade 8 Algebra Skill Taxonomy

Status: DONE
Codex: MOSTLY NO

## Goal

Define a small, controlled, stable skill taxonomy for the first supported Grade 8 algebra curriculum slice.

The taxonomy must give Tutor Engine, Verifier, Attempt, Mastery and future evaluation code one shared vocabulary for describing what a student is practicing or misunderstanding.

This task defines the data specification only.

It does NOT implement the runtime skill registry.

## Context

The current application already passes skill identifiers as strings through several boundaries:

- `Skill.code`
- `Mastery.skill_code`
- `Attempt.skill_code`
- `TutorSession.primary_skill`
- `ProblemAnalysis.skills`
- `TutorTurn.skill_tags`

Existing code and eval data already use identifiers such as:

- `algebra.linear_equation`
- `algebra.factorization`
- `algebra.rational_expression.domain`
- `general.problem_solving`

The current `Skill` persistence model already contains:

- code
- name
- subject
- grade_min
- grade_max
- prerequisite_codes

M07-02 will implement a controlled registry from the specification produced here.

Unknown labels from an LLM must not silently create new curriculum skills.

## Initial curriculum slice

M07-01 v1 should cover only the algebra families already needed by the current Tutor Engine, eval cases and near-term verifier work.

The first slice must include skills for:

1. Algebraic expression manipulation.
2. Algebraic identities needed for factorization.
3. Polynomial factorization.
4. Rational-expression domain conditions.
5. Rational-expression simplification at a basic level.
6. One-variable linear equations.
7. Arithmetic prerequisites required by those skills.

Do not attempt to model the entire Grade 8 mathematics curriculum in this task.

Geometry and unrelated subject areas are out of scope.

## Skill code convention

Skill codes are stable application identifiers.

Use lowercase dot-separated codes.

Examples:

`algebra.linear_equation`

`algebra.factorization`

`algebra.rational_expression.domain`

Rules:

- codes are machine identifiers, not display labels;
- once released, a code should not be renamed casually;
- Vietnamese wording belongs in display names and aliases, not in the code;
- one code should represent one observable skill;
- avoid overly broad codes when student evidence cannot distinguish the underlying skill;
- avoid extremely fine-grained codes that cannot be measured independently.

## Taxonomy record contract

Each reviewed curriculum skill must define:

- `code`
- `name_vi`
- `subject`
- `grade_min`
- `grade_max`
- `prerequisites`
- `aliases`
- `observable_mastery_evidence`
- `common_misconceptions`
- `verifier_family`

### code

Stable dot-separated application identifier.

### name_vi

Short Vietnamese learner/teacher-facing name.

### subject

For this task:

`math`

### grade_min / grade_max

Initial Grade 8 skills normally use:

`8`

unless a prerequisite intentionally comes from an earlier grade.

### prerequisites

List of other controlled skill codes required before this skill.

Prerequisites must form an acyclic graph.

Do not use free-text prerequisite labels.

### aliases

Common labels that an analyzer or future normalization layer may encounter.

Aliases are recognition aids only.

Aliases must never create a new skill automatically.

### observable_mastery_evidence

Describe what a student must be able to do for the system to have evidence of this skill.

Evidence must be observable from student work or verified attempts.

Do not define mastery as:

"the model thinks the student understands it."

### common_misconceptions

Small controlled list of characteristic errors useful for future misconception evidence.

M07-01 defines the vocabulary only.

It does not implement misconception persistence.

### verifier_family

Indicates what deterministic verifier strategy is expected later.

Allowed v1 values:

- `numeric`
- `linear_equation`
- `expression_equivalence`
- `factorization`
- `domain_condition`
- `manual_or_future`

This is routing metadata, not verifier implementation.

## Reserved / fallback labels

`general.problem_solving` may remain as a temporary demo/fallback label but is NOT considered a mastered Grade 8 algebra curriculum skill.

The controlled registry implemented in M07-02 must have an explicit UNKNOWN outcome for unrecognized LLM labels.

UNKNOWN must not silently become a new Skill row and must not update student mastery.

Exact runtime representation of UNKNOWN belongs to M07-02.

## Required v1 skill families

The reviewed taxonomy must contain enough skills to represent at least these existing examples:

- solving `2x + 3 = 11`;
- factorizing `x^2 - 5x + 6`;
- finding the domain condition of `(x+1)/(x-2)`.

The taxonomy should distinguish prerequisites when they represent independently observable weaknesses.

For example, failure to solve a linear equation may come from:

- signed-number arithmetic;
- distributive property;
- combining like terms;
- preserving equality while transforming an equation.

Do not collapse all of these into `algebra.linear_equation` if doing so would prevent useful diagnosis.

## Draft v1 canonical skills

The first reviewed taxonomy slice contains exactly these mastery-bearing skills:

| Code | Vietnamese name | Direct prerequisites |
|---|---|---|
| `arithmetic.signed_number_operations` | Thực hiện phép tính với số có dấu | — |
| `algebra.expression.distributive_property` | Áp dụng tính chất phân phối | `arithmetic.signed_number_operations` |
| `algebra.expression.combine_like_terms` | Thu gọn hạng tử đồng dạng | `arithmetic.signed_number_operations` |
| `algebra.expression.simplify` | Thu gọn biểu thức đại số | `algebra.expression.distributive_property`, `algebra.expression.combine_like_terms` |
| `algebra.equation.equivalent_transform` | Biến đổi tương đương phương trình | `algebra.expression.simplify` |
| `algebra.linear_equation` | Giải phương trình bậc nhất một ẩn | `algebra.equation.equivalent_transform` |
| `algebra.identity.basic` | Nhận biết và vận dụng hằng đẳng thức cơ bản | `algebra.expression.distributive_property`, `algebra.expression.combine_like_terms` |
| `algebra.factorization` | Phân tích đa thức thành nhân tử | `algebra.expression.simplify` |
| `algebra.rational_expression.domain` | Tìm điều kiện xác định của phân thức | `algebra.linear_equation` |
| `algebra.rational_expression.simplify` | Rút gọn phân thức đại số | `algebra.factorization`, `algebra.rational_expression.domain` |

### Prerequisite notes

The graph above must remain acyclic.

Direct prerequisites list only immediate dependencies, not transitive prerequisites.

`algebra.identity.basic` is not a universal prerequisite of `algebra.factorization`.

Some factorization problems use algebraic identities, but the current supported factorization example `x^2 - 5x + 6` does not require them. Problem-specific prerequisite selection may include both skills later without making identity knowledge a global prerequisite for all factorization.

`algebra.rational_expression.domain` depends on basic linear-equation solving because even a simple denominator such as `x - 2` requires deriving and solving the excluded-value condition.

### Current eval mapping

| Eval problem | Primary controlled skill |
|---|---|
| `2x + 3 = 11. Tìm x.` | `algebra.linear_equation` |
| `3x - 5 = 10. Tìm x.` | `algebra.linear_equation` |
| `x^2 - 5x + 6` factorization | `algebra.factorization` |
| `(x+1)/(x-2)` domain condition | `algebra.rational_expression.domain` |

`general.problem_solving` is deliberately excluded from this table because it is a fallback label rather than a mastery-bearing curriculum skill.

## Acceptance criteria

M07-01 is DONE only when:

- a reviewed Grade 8 algebra v1 taxonomy exists;
- every curriculum skill has a stable controlled code;
- every skill has a Vietnamese display name;
- every skill defines prerequisites;
- the prerequisite graph has no cycles;
- every skill defines observable mastery evidence;
- common misconceptions are specified where meaningful;
- every skill has verifier-family routing;
- existing eval examples can be mapped to controlled codes;
- `algebra.linear_equation` is represented;
- `algebra.factorization` is represented;
- `algebra.rational_expression.domain` is represented;
- UNKNOWN behavior for future registry normalization is explicitly defined;
- `general.problem_solving` is not treated as a mastery-bearing curriculum skill;
- no application code or database schema changes are made.

## Validation

M07-01 requires design validation rather than backend implementation tests.

Before marking DONE:

1. Check every prerequisite code exists in the taxonomy.
2. Check the prerequisite graph for cycles.
3. Check all skill codes are unique.
4. Check all aliases map to exactly one intended controlled skill or are explicitly marked ambiguous.
5. Map the current algebra eval cases to the taxonomy.
6. Review whether each mastery claim is supported by observable student evidence rather than LLM judgment alone.

M07-02 will add runtime registry tests.

## Stop conditions

Stop and split the task instead of expanding scope if:

- the taxonomy grows into the full mathematics curriculum;
- a database migration appears necessary;
- TutorAI behavior must change;
- verifier implementation is required;
- mastery logic must change;
- another subject must be added.
