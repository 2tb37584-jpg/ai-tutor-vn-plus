## Question contract

Each JSON record must use exactly these fields:

```text
id
skill_code
problem_text
verification_reference
expected_answer
verification_family
```

### id

- non-empty canonical string;
- unique across the bank;
- stable identifier;
- no student/session identifiers.

Suggested format:

```text
g8alg.<skill-slug>.<nnn>
```

### skill_code

- must be a canonical controlled skill code;
- aliases are not accepted;
- must be mastery-bearing;
- the skill's `verifier_family` must equal the question's `verification_family`.

### problem_text

- non-empty Vietnamese-first student-facing problem text;
- must not include the final answer;
- must be self-contained;
- no PII;
- no external links;
- no image requirement in v1.

### verification_reference

- non-empty internal deterministic verification reference;
- never intended as student-facing content;
- family-specific semantics:
  - `numeric`: expected numeric reference;
  - `expression_equivalence`: reference expression;
  - `linear_equation`: parseable equation string such as `2*x-3=9`;
- must be directly consumable by the current deterministic verifier without rerunning the analyzer.

### expected_answer

- non-empty internal correct answer/candidate;
- never intended as student-facing content;
- together with `verification_reference`, must produce deterministic `CORRECT` through the current production verifier.

### verification_family

Allowed in v1 only:

```text
numeric
expression_equivalence
linear_equation
```

Do not seed unsupported families such as:

```text
factorization
domain_condition
manual_or_future
```

## Typed module

Create `backend/app/services/question_bank.py`.

Required immutable type:

```python
@dataclass(frozen=True)
class QuestionBankItem:
    id: str
    skill_code: str
    problem_text: str
    verification_reference: str
    expected_answer: str
    verification_family: str
```

Required public functions:

```python
get_all_questions() -> tuple[QuestionBankItem, ...]
get_question(question_id: str) -> QuestionBankItem | None
get_questions_for_skill(skill_code: str) -> tuple[QuestionBankItem, ...]
```

Behavior:

### get_all_questions

- returns the full immutable tuple;
- preserves JSON declaration order.

### get_question

- exact canonical ID lookup only;
- unknown ID -> `None`.

### get_questions_for_skill

- canonical skill code only;
- preserve bank declaration order;
- unknown code -> `()`;
- alias input -> `()`;
- no implicit skill alias resolution.

## Loader validation

Validate at module load/build time:

- top-level JSON shape is a non-empty list;
- each item has exactly the six required fields;
- each field has the expected string type;
- no required string is blank;
- IDs are unique;
- `skill_code` is canonical and mastery-bearing;
- alias labels are rejected;
- `verification_family` is one of the three supported v1 families;
- question family matches the controlled skill definition's `verifier_family`;
- `verification_reference` + `expected_answer` can be routed through the current typed production verifier for the declared family and returns `CORRECT`;
- bank contains exactly 12 records;
- family distribution is exactly 4 / 4 / 4.

Prefer a small private `_build_question_bank(records)` helper so tests can validate malformed fixtures without editing production JSON.

Do not add a second skill registry or duplicate taxonomy metadata.
