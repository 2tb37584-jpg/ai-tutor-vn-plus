# M07-03 — Expose Curriculum Prerequisite Graph Queries

Status: READY
Codex: YES
Module: M07 Skill Graph
Phase: Phase 3 — Adaptive Learning

## Direction gate

Roadmap link: Phase 3 — curriculum prerequisite graph
Core-loop impact: Mastery state -> prerequisite-aware next learning action
Why now: The taxonomy already stores validated prerequisite edges, but runtime code has no small public query seam for consuming the graph.
Why not defer: Adaptive recommendation should reuse one controlled graph contract instead of re-reading taxonomy JSON or duplicating prerequisite logic elsewhere.
Exit criterion affected: prerequisite-aware sequencing can be implemented and tested without introducing a second graph source of truth.

## Goal

Expose a minimal, immutable prerequisite graph query API from the existing skill registry.

Do not add a new graph service, database model, migration, dependency, or taxonomy file.

## Context

The current taxonomy already contains:

```text
SkillDefinition.prerequisites
```

The registry already validates:

```text
every prerequisite references an existing skill
the prerequisite graph has no cycle
```

Therefore the taxonomy + SkillRegistry remain the single source of truth.

## Micro-task

Add query helpers for direct graph traversal only.

Required public behavior:

```text
get_skill_definition(code)
get_direct_prerequisites(code)
get_direct_dependents(code)
```

Do not add mastery thresholds, recommendation policy, remediation ranking, or next-skill selection in this task.

## Contract

### get_skill_definition

Input:

```text
canonical skill code
```

Return:

```text
SkillDefinition | None
```

Unknown/non-canonical values return `None`.

Do not resolve aliases implicitly here. Callers that want alias resolution must use the existing `resolve_skill_code(...)` first.

### get_direct_prerequisites

Input:

```text
canonical skill code
```

Return:

```text
tuple[str, ...]
```

Behavior:

- preserve taxonomy order;
- return direct prerequisites only;
- unknown/non-canonical input returns empty tuple;
- never mutate registry state.

### get_direct_dependents

Input:

```text
canonical skill code
```

Return:

```text
tuple[str, ...]
```

Behavior:

- return skills that directly name the input code as a prerequisite;
- preserve taxonomy declaration order;
- direct dependents only;
- unknown/non-canonical input returns empty tuple;
- never mutate registry state.
