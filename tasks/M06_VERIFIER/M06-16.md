# M06-16 — Separate Registered Verifier Families from Tutor Runtime-Supported Families

Status: READY
Codex: YES
Module: Verifier / Tutor Integration

## Goal

Restore the invariant that `TutorSession.verification_family` is persisted only for verifier families that the tutor runtime can actually reconstruct into a deterministic `VerificationRequest` from trusted persisted session context.

`ProblemFamily` enum registration alone must not imply tutor-runtime support.

This task exists to unblock `M06-15`.

## Context

`M06-15` added a deterministic `factorization` verifier family in an implementation diff.

Focused verifier tests passed:

```text
109 passed
```

The full backend suite then exposed one integration failure:

```text
523 passed, 1 failed
```

Failure:

```text
tests/test_tutor_verification_context.py::
test_start_persists_only_registry_backed_implemented_verifier_families
```

Observed mismatch:

```text
skill.factorization
registry verifier_family = factorization

expected TutorSession.verification_family = None
actual TutorSession.verification_family = "factorization"
```

Repository inspection established:

```python
def _verification_family_for_primary_skill(primary_skill: str) -> str | None:
    for skill in get_controlled_skills():
        if skill.code != primary_skill:
            continue
        try:
            return ProblemFamily(skill.verifier_family).value
        except ValueError:
            return None
    return None
```

This currently treats any registered `ProblemFamily` as tutor-runtime supported.

But `_verification_request_for_session()` currently constructs requests only for:

```text
numeric
expression_equivalence
linear_equation
```

and returns `None` for other families.

Therefore adding `ProblemFamily.FACTORIZATION` creates an inconsistent session state:

```text
family persisted
BUT
runtime cannot construct the deterministic request
```

`M06-15` is BLOCKED until this invariant is restored.

## Micro-task

Separate:

```text
registered verifier family
```

from:

```text
TutorSession runtime-supported verifier family
```

The implementation must keep `factorization` unpersisted for normal TutorSession verification until a separately reviewed trusted factorization request-construction contract exists.

Do not wire factorization runtime verification in this task.

## Required design

Introduce a small explicit source of truth in `backend/app/api/tutor.py` for families that are supported by `_verification_request_for_session()`.

The implementation may use either:

```python
_TUTOR_RUNTIME_VERIFICATION_FAMILIES = {
    ProblemFamily.NUMERIC,
    ProblemFamily.EXPRESSION_EQUIVALENCE,
    ProblemFamily.LINEAR_EQUATION,
}
```

or an equivalent small private helper.

The key invariant is:

```text
_verification_family_for_primary_skill()
must return a family only when:

1. the skill exists in the controlled registry;
2. its canonical verifier_family maps to a registered ProblemFamily;
3. that ProblemFamily is explicitly supported by tutor runtime request construction.
```

For any registered-but-not-runtime-supported family such as `factorization`:

```text
return None
```

Do not infer support merely from enum membership.

## Runtime support contract

`manual_or_future` remains unsupported.

Unknown families remain unsupported.
