# M06-10 — Persist Trusted Verifier Family Context

Status: ACTIVE
Codex: YES
Module: M06 Math Verifier
Phase: Phase 2 — Correctness

## Direction gate

Roadmap link: Phase 2 — deterministic verifier integration
Core-loop impact: Problem analysis -> persisted verifier routing context -> future live verification
Why now: M06-11 cannot build deterministic verifier requests safely across `/start` and `/reply` without persisted routing metadata.
Why not defer: Deferring would force live orchestration to guess a verifier family or re-parse `normalized_problem`.
Exit criterion affected: >=98% correctness on the supported initial domain.

## Goal

Persist the current supported deterministic verifier family on `TutorSession` at `/tutor/start`.

This task establishes only the persistence boundary.

Do not call the verifier and do not change `/tutor/reply` behavior.

## Minimal design

Add exactly one nullable internal session field:

```text
verification_family: str | None
```

Do not add `verification_reference` or `verification_variable`.

Existing persisted fields already provide the future verifier reference:

```text
NUMERIC
    reference -> session.internal_expected_answer

EXPRESSION_EQUIVALENCE
    reference -> session.internal_expected_answer

LINEAR_EQUATION
    reference -> session.normalized_problem
```

Candidate answers remain request-time student input and are not persisted by this task.

## Routing authority

The skill taxonomy/registry is the only routing authority.

For the session's existing `primary_skill`:

1. match it to a controlled canonical skill definition;
2. read that definition's `verifier_family`;
3. persist the family only if it is one of the currently implemented deterministic `ProblemFamily` values;
4. otherwise persist `None`.

Current supported values:

```text
expression_equivalence
linear_equation
numeric
```

Examples such as these must NOT be persisted as supported deterministic families:

```text
factorization
domain_condition
manual_or_future
unknown/general skill
```

Do not infer a family from problem text, expected answer, aliases, or model prose.

## Important trust boundary

`verification_family` is trusted routing metadata because it comes from the controlled registry.

The reference strings are still verifier inputs, not pre-verified truth.

In particular:

```text
session.normalized_problem
```

must not be treated as a guaranteed valid linear equation. A later verifier may return `UNSUPPORTED`.
