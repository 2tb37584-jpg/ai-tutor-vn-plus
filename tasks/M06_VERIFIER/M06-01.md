# M06-01 — Linear Equation Verifier Hardening

Status: DONE
Codex: YES

## Goal

Safely and deterministically analyze and verify candidate solutions for supported one-variable linear equations.

The verifier must reject malformed, unsafe, multi-symbol and non-linear inputs rather than trusting SymPy to interpret arbitrary expressions.

This task covers one-variable linear equations only.

Expression-equivalence hardening belongs to M06-02.

## Context

The current verifier contains:

- `_parse_safe()`
- `equivalent()`
- `solve_simple_equation()`

`solve_simple_equation()` currently delegates directly to `sympy.solve()` after only basic character filtering.

It has no production consumer yet; it is referenced only by verifier tests.

This gives M06-01 room to introduce a stricter internal verifier contract without changing TutorAI, Tutor API, mastery or persistence.

SymPy is already an existing dependency:

`sympy>=1.14,<2`

No new dependency is needed.

## Module / micro-task

Module:

`M06 Math Verifier`

Micro-task:

Add deterministic validation/classification for one-variable linear equations and candidate solutions while preserving the existing `solve_simple_equation()` compatibility wrapper.

## Supported equation domain

M06-01 supports equations reducible to a polynomial of degree at most 1 in exactly one selected variable.

Examples of supported unique-solution equations:

- `2*x + 3 = 7`
- `x/2 + 1 = 3`
- `3*(x - 2) = 9`

The default variable is:

`x`

The existing parser may recognize `x`, `y`, and `z`, but a verifier call must reject any equation containing a symbol other than the selected variable.

For example:

`2*x + y = 7`

must be rejected when verifying for `x`.

## Unsupported inputs

Reject deterministically:

- missing `=`;
- more than one `=`;
- empty left or right side;
- unsupported characters;
- arbitrary Python/code-like input;
- function names;
- multiple symbols;
- symbols other than the selected variable;
- non-linear equations such as `x^2 = 4`;
- multiplicative non-linearity such as `x*x = 4`;
- variable-in-denominator equations such as `1/x = 2`;
- malformed expressions;
- invalid variable names.

Do not attempt to broaden the parser in this task.

## Variable contract

Supported variable names for this v1 verifier are:

- `x`
- `y`
- `z`

A different requested variable must be rejected deterministically.

Do not dynamically create arbitrary symbol names from untrusted input.

## Equation classification

Internally distinguish at least:

- unique solution;
- no solution;
- infinitely many solutions;
- invalid / unsupported equation.

Examples:

`2*x + 3 = 7`
→ unique solution

`x + 1 = x + 2`
→ no solution

`x + 1 = x + 1`
→ infinitely many solutions

`x^2 = 4`
→ invalid / unsupported for this verifier

The classification representation may be a small Enum/dataclass or an equally explicit typed internal structure.

Do not encode these cases through exceptions exposed to callers.

## Candidate verification

Add a deterministic public function for checking a candidate solution.

Recommended API:

```python
verify_linear_equation_solution(
    equation: str,
    candidate: str,
    variable: str = "x",
) -> bool
```

Return `True` only when:

1. the equation is valid within the supported M06-01 domain;
2. it has a unique solution;
3. the candidate is a safe scalar expression with no free symbols;
4. the candidate satisfies the equation.

Otherwise return `False`.

Examples:

`verify_linear_equation_solution("2*x+3=7", "2")`
→ `True`

`verify_linear_equation_solution("2*x+3=7", "3")`
→ `False`

`verify_linear_equation_solution("2*x+3=7", "1+1")`
→ `True`

`verify_linear_equation_solution("x^2=4", "2")`
→ `False`

`verify_linear_equation_solution("2*x+y=7", "2")`
→ `False`

Unsafe or malformed candidates must return `False`.

## Existing compatibility API

Keep:

```python
solve_simple_equation(equation: str, variable: str = "x") -> list[str]
```

For backward compatibility:

- return a one-item list for a supported unique-solution equation;
- return `[]` for no solution;
- return `[]` for infinitely many solutions;
- return `[]` for invalid or unsupported equations.

Example:

`solve_simple_equation("2*x+3=7") == ["2"]`

Do not use `solve_simple_equation()` to represent the full classification contract.

## Parsing and safety

Keep deterministic allow-list parsing.

Do not use:

- Python `eval`;
- `exec`;
- dynamic imports;
- arbitrary SymPy names/functions;
- unrestricted `parse_expr` locals.

After parsing, inspect free symbols explicitly.

The equation must contain no free symbols other than the selected variable.

Candidate expressions must contain no free symbols.

## Linearity validation

Do not classify an equation as supported merely because `sympy.solve()` returns a value.

Explicitly establish that the simplified equation is linear/constant in the selected variable.

A suitable approach is to examine the simplified `lhs - rhs` as a polynomial in the selected symbol and reject expressions that cannot be represented as such or have degree greater than 1.

Do not solve non-linear equations and then accept their roots.

## Existing `equivalent()` behavior

Do not redesign or expand `equivalent()` in M06-01.

Existing equivalence tests must continue to pass.

M06-02 owns expression-equivalence hardening.

Only make the smallest changes required if shared parser safety must remain compatible.

## Acceptance criteria

M06-01 is complete when:

- supported one-variable linear equations are recognized deterministically;
- unique solutions are computed correctly;
- no-solution and infinite-solution cases are distinguished internally;
- malformed equations are rejected safely;
- multiple `=` inputs are rejected;
- multiple-symbol equations are rejected;
- non-selected symbols are rejected;
- non-linear equations are rejected;
- variable-denominator equations are rejected;
- arbitrary code-like input is rejected;
- candidate verification accepts correct scalar candidates;
- candidate verification rejects incorrect candidates;
- candidate verification rejects symbolic candidates;
- invalid equations never become verified because SymPy happened to solve them;
- `solve_simple_equation()` retains its existing list-return compatibility behavior;
- existing `equivalent()` tests continue passing;
- no new dependency is added;
- targeted verifier tests pass;
- full backend regression passes.
