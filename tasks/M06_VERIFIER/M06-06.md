# M06-06 — Add Exact Numeric Verification Adapter

Status: ACTIVE
Codex: YES
Module: M06 Math Verifier
Phase: Phase 2 — Correctness

## Goal

Add an exact scalar numeric verifier adapter to the deterministic verification seam introduced by M06-04.

Support only the numeric literal domain defined by M06-05.

Do not add unit support.

## Context

M06-05 established:

- current eval corpus: 100 cases;
- real unit-bearing cases: 0;
- current verifier fixtures: 8, all `linear_equation`;
- current schema has no typed unit metadata;
- first numeric verifier should be exact-only;
- no default tolerance or implicit rounding;
- no new dependency is justified.

The new adapter must reuse the existing:

```python
ProblemFamily
VerificationStatus
VerificationResult
VerificationRequest
verify(...)
```

contract.

Existing verifier families must remain unchanged:

```text
EXPRESSION_EQUIVALENCE
LINEAR_EQUATION
```

## Required implementation

### Problem family

Add:

```python
ProblemFamily.NUMERIC
```

### Request type

Add an immutable typed request:

```python
@dataclass(frozen=True)
class NumericVerificationRequest:
    family: ProblemFamily
    expected: str
    candidate: str
```

Add it to `VerificationRequest`.

### Supported numeric forms

Support only scalar real rational literals:

```text
integer
signed integer
finite decimal
signed finite decimal
fraction a/b
signed fraction
outer whitespace
```

Examples:

```text
4
-8
+3
0
0.5
-2.75
1/2
-7/3
```

Normalize supported literals to exact rational values.

Preferred implementation:

```python
fractions.Fraction
```

with conservative validation before conversion.

### Exact comparison

No tolerance.

No implicit rounding.

Examples:

```text
0.5 == 1/2
0.1 == 1/10
3.14 == 3.140
0.333 != 1/3
```

### Unsupported forms

Return `UNSUPPORTED` for:

```text
1/0
x
1+2
sqrt(2)
pi
1e-3
25%
3 cm
NaN
Infinity
1,5
```

Also reject:

```text
intervals
inequalities
vectors
complex values
mixed-number notation
unit-bearing strings
```

### Status mapping

```text
supported expected + supported candidate + exact equality
    -> CORRECT

supported expected + supported candidate + different value
    -> INCORRECT

known malformed/unsupported numeric syntax/domain
    -> UNSUPPORTED

unexpected internal/runtime failure
    -> INDETERMINATE
```

Do not collapse unexpected runtime failures into `UNSUPPORTED`.

### Router integration

Extend the existing deterministic `verify()` router.

A NUMERIC request must route only to the numeric adapter.

Mismatched family/request type must continue to return `UNSUPPORTED`.

No fuzzy routing.

No LLM routing.

No fallback into expression equivalence.

## Backward compatibility

Do not change behavior or public signatures of existing verifier APIs, including:

```python
equivalent(...)
classify_linear_equation(...)
verify_linear_equation_solution(...)
solve_simple_equation(...)
```

Existing expression and linear-equation adapter tests must continue to pass.
