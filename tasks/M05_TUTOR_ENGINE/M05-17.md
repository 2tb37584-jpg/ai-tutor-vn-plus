# M05-17 — Add Trusted Authored-Question Start Endpoint

Status: DONE
Codex: YES — SMALL
Module: Tutor Engine

## Goal

Add a trusted backend endpoint that starts a new tutor session from a server-owned question-bank item selected by `question_id`.

The authored start path must preserve question identity, skill, hidden answer, verifier family, and difficulty authority from the server-side question bank.

This task is backend-only.

Do not change the frontend yet.

## Context

The adaptive-learning flow now has:

```text
M05-15
TutorSession.authored_question_id persistence

M05-16
authored_question_id
→ get_question(...)
→ verification_request_for_candidate(...)
→ deterministic non-transfer verification
```

M05-17 completes the backend start seam so the learner can later choose a recommended question.

The existing free-form endpoint remains:

```text
POST /tutor/start
```

with:

```text
student_id
problem_text
image_data_url
```

and uses:

```text
ai.analyze_problem(...)
```

That free-form behavior must remain unchanged.

The authored path has a different trust model:

```text
client chooses question_id
server owns the question content and verification truth
```

## Endpoint contract

Add:

```text
POST /tutor/start-authored
```

Request:

```json
{
  "student_id": 123,
  "question_id": "g8alg.factorization.001"
}
```

Response:

```json
{
  "session_id": 456,
  "question": {
    "question_id": "g8alg.factorization.001",
    "skill_code": "algebra.factorization",
    "problem_text": "...",
    "difficulty": 2
  },
  "tutor": {
    "...": "existing TutorTurn fields"
  }
}
```

Do not expose expected-answer or verifier internals.

## Request schema

Add a schema equivalent to:

```python
class StartAuthoredTutorRequest(BaseModel):
    model_config = ConfigDict(extra="forbid")

    student_id: int
    question_id: str = Field(min_length=1, max_length=120)
```

Import `ConfigDict` from Pydantic if needed.

The authored request must not accept authoritative client copies of:

```text
problem_text
skill_code
difficulty
expected_answer
verification_reference
verification_family
```

Using `extra="forbid"` is required so client override attempts fail validation rather than being silently ignored.

Do not change the behavior/configuration of existing request schemas.

## Response schema

Add:

```python
class StartAuthoredTutorResponse(BaseModel):
    session_id: int
    question: NextLearningAction
    tutor: TutorTurn
```

Reuse existing:

```python
NextLearningAction
```

as the learner-safe authored question projection.

Do not add:

```text
expected_answer
verification_reference
verification_family
```

to the public response.

## Lookup and ownership contract

The endpoint must:

1. verify the authenticated user owns `student_id`;
2. resolve the authored item using:
   `get_question(payload.question_id)`;
3. return 404 for unknown question ID;
4. create no `TutorSession` and no `TutorMessage` on unknown ID;
5. never fall back to the free-form analyzer path.

Recommended error:

```text
HTTP 404
detail = "Question not found"
```

Ownership checks should retain the existing `owned_student(...)` behavior.

## No model analysis

The authored path must never call:

```python
ai.analyze_problem(...)
```

The following fields are trusted from the question-bank item:

```text
normalized_problem       = item.problem_text
primary_skill            = item.skill_code
internal_expected_answer = item.expected_answer
verification_family      = item.verification_family
authored_question_id     = item.id
```

`transfer_question_id` must remain null on initial creation.

## Deterministic internal analysis for first turn

The existing tutor generation API uses:

```python
ai.first_turn(analysis, student.grade)
```

Construct a deterministic internal `ProblemAnalysis` from the authored item.

Required authoritative fields:

```python
ProblemAnalysis(
    normalized_problem=item.problem_text,
    subject="math",
    grade_band="8",
    skills=[item.skill_code],
    prerequisites=[],
    expected_answer=item.expected_answer,
    verification_notes="",
    confidence=1.0,
)
```

If existing project conventions use a different deterministic Grade 8 string, follow that existing convention if found inside allowed files/tests; otherwise `"8"` is acceptable for this endpoint.

These presentation-oriented analysis fields are not new verifier authority.

Do not call the model analyzer to populate them.

## Session construction

Create:

```python
TutorSession(
    student_id=student.id,
    title=item.problem_text[:220] or "Tutoring session",
    normalized_problem=item.problem_text,
    primary_skill=item.skill_code,
    internal_expected_answer=item.expected_answer,
    verification_family=item.verification_family,
    authored_question_id=item.id,
)
```

Do not explicitly populate `transfer_question_id`; it must remain its nullable default.

The endpoint should follow the existing start transaction structure:

```text
db.add(session)
db.flush()
generate first turn
guard first turn
persist assistant TutorMessage
db.commit()
return response
```

## First tutor turn

Generate the first tutor turn with:

```python
ai.first_turn(analysis, student.grade)
```

The first turn must still pass through:

```python
_guard_tutor_turn(tutor_turn, item.expected_answer)
```

This ensures authored starts preserve existing answer-leakage protection.

Do not special-case authored content to bypass the guard.

The initial state is whatever the existing `first_turn` contract returns after guarding.

Do not force:

```text
TRANSFER
COMPLETE
```

merely because the item came from a recommendation.

```python
StartAuthoredTutorResponse(
```

```text
session.internal_expected_answer
```

## Transaction / failure behavior

### Unknown question

Before session creation:

```text
get_question(...) -> None
→ HTTP 404
→ no db.add(TutorSession)
→ no db.flush()
→ no TutorMessage
→ no commit
```

### Ownership failure

Existing `owned_student(...)` failure behavior remains authoritative.

Do not lookup/create a session for a student the user does not own.

### First-turn generation failure

Do not add custom partial-commit behavior.

Preserve the existing transaction expectation that commit occurs only after session + first assistant message are ready.
