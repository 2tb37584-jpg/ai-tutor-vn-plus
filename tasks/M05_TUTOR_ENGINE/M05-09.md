# M05-09 — Persist Authored Transfer Item Identity

Status: DONE
Codex: YES
Module: Tutor Engine

## Goal

Persist the identity of the authored transfer question selected for a tutor session.

Add a nullable `transfer_question_id` field to `TutorSession`, backed by one deterministic Alembic migration, so a later tutor request can reconstruct the exact authored transfer item instead of guessing from skill alone.

This task is persistence-only.

## Context

M05-07 remains blocked because the runtime cannot deterministically complete a transfer interaction.

M05-08 established that deterministic transfer completion must operate on the exact authored transfer item selected for the session.

The current runtime cannot do that because `TutorSession` does not persist transfer-item identity.

The verifier/coverage prerequisites are now available:

- M06-15 — deterministic factorization verifier;
- M06-17 — deterministic domain-condition verifier;
- M07-06 — authored deterministic transfer coverage for all currently eligible mastery-bearing skills.

This task must not implement transfer orchestration.

## Persistence contract

Add a nullable persisted field conceptually equivalent to:

```python
transfer_question_id: Mapped[str | None] = mapped_column(
    String(...),
    nullable=True,
)
```

Follow the existing SQLAlchemy style used by `TutorSession`.

Choose the string length consistently with existing project identifier fields.

Do not invent a relationship or database table for authored question-bank items.

The value is an opaque authored question-bank ID such as:

```text
g8alg.factorization.001
```

The database does not validate that the ID exists in the JSON question bank in this task.

Validation/reconstruction belongs to a later application-layer task.
