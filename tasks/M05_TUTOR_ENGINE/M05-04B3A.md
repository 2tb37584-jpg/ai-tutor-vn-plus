# M05-04B3A — Add Deterministic Answer-Leakage Detector

Status: DONE
Codex: YES — SMALL

## Goal

Add a deterministic, model-independent detector that identifies when a tutor message appears to reveal the internal expected answer.

This task implements detection only.

It does NOT modify TutorAI generation.
It does NOT modify tutor API behavior.
It does NOT decide which TutorState may reveal the final answer.

## Context

TutorTurn currently contains:

- `message`
- `reveal_final_answer`

However, `reveal_final_answer` is produced by the same model that generates the message and is currently not enforced.

The application now also has durable server-internal expected-answer data from M05-04B1/B2.

Generation and verification should remain separate.

A later task, M05-04B3B, will combine this detector with tutor-state policy before a TutorTurn is persisted or returned to the student.

## Allowed implementation files

- backend/app/services/answer_leakage.py
- backend/tests/test_answer_leakage.py

## Detector contract

Create a small deterministic service function conceptually equivalent to:

`detects_final_answer_leak(message, expected_answer, model_reports_reveal) -> bool`

Exact naming may vary if clearer.

The detector must not call an LLM or external service.

The detector must not depend on TutorState.

Tutor-state permission is integration policy and belongs to M05-04B3B.

## Required behavior

### Model self-report

If `model_reports_reveal` is true, detection must return true.

Do not trust a false value as proof that the message is safe.

### Empty expected answer

If the expected answer is empty or whitespace-only:

- do not report a textual expected-answer match;
- `model_reports_reveal=True` must still be detected.

### Deterministic normalization

For textual comparison, normalize enough to handle ordinary formatting variation:

- Unicode normalization;
- case-insensitive comparison;
- collapse irrelevant whitespace;
- normalize common spacing around simple mathematical operators such as `=`.

Do not attempt symbolic algebra or semantic equivalence in this task.

### Structured or sufficiently distinctive answers

If a normalized expected answer is sufficiently distinctive and appears directly in the normalized tutor message, detect it.

Examples that should be detected include conceptually:

- expected: `x = 2`
- message: `Vậy x=2.`

and:

- expected: `Hà Nội`
- message: `Đáp án là Hà Nội.`

### Short scalar answers

Do NOT use naive substring matching for short scalar answers.

For example, with expected answer `2`:

`Hãy thử cộng 2 vào hai vế.`

must NOT be classified as final-answer leakage merely because the digit appears.

But answer-like disclosures such as:

`Đáp án là 2.`

or:

`Vậy x = 2.`

must be detected.

Use a small deterministic set of answer-like cues/patterns rather than semantic inference.

Keep the implementation conservative and readable.

## Non-goals

Do NOT implement:

- symbolic mathematical equivalence;
- equation solving;
- semantic similarity embeddings;
- LLM-based verification;
- TutorState policy;
- message replacement/fallback behavior;
- API enforcement;
- logging/analytics infrastructure.

Those are outside this micro-task.

## Acceptance criteria

- Detector is deterministic.
- Detector has no LLM/external calls.
- `model_reports_reveal=True` always triggers detection.
- False self-report does not bypass textual detection.
- Empty expected answer is handled safely.
- Normal formatting differences such as `x = 2` versus `x=2` are handled.
- Distinctive expected-answer disclosure is detected.
- Short scalar occurrence in an instructional context does not automatically trigger.
- Short scalar answer-like disclosure does trigger.
- Existing production files outside the new detector remain unchanged.
- Only the two allowed implementation files change.
- Full backend tests remain green.

## Required tests

Add focused unit tests covering at minimum:

1. model self-report true;
2. model self-report false with no textual leak;
3. empty expected answer;
4. structured answer:
   - expected `x = 2`
   - message contains `x=2`
   - detected;
5. case/whitespace normalization;
6. text answer:
   - expected `Hà Nội`
   - direct answer disclosure
   - detected;
7. short scalar false-positive protection:
   - expected `2`
   - `Hãy thử cộng 2 vào hai vế.`
   - NOT detected;
8. short scalar answer cue:
   - expected `2`
   - `Đáp án là 2.`
   - detected;
9. short scalar assignment:
   - expected `2`
   - `Vậy x = 2.`
   - detected.

Run targeted:

`docker compose exec backend pytest -q tests/test_answer_leakage.py`

Then full backend:

`docker compose exec backend pytest -q`
