# M05-04B3B — Enforce Runtime Answer-Leakage Guard In Tutor API

Status: DONE
Codex: YES — SMALL

## Goal

Enforce the deterministic answer-leakage detector at the student-facing tutor API boundary before tutor output is persisted or returned.

This task integrates the detector created in M05-04B3A.

It does NOT change TutorAI generation or tutor state transitions.

## Context

M05-04B3A added a deterministic detector:

`detects_final_answer_leak(...)`

M05-04B1/B2 provide durable server-internal expected-answer data:

- `/tutor/start`: `ProblemAnalysis.expected_answer`
- `/tutor/reply`: `TutorSession.internal_expected_answer`

`TutorTurn.reveal_final_answer` is generated by the model and cannot be trusted by itself.

Generation and leakage verification must remain separate.

## Runtime policy

Final-answer disclosure is permitted only when the resulting TutorTurn state is:

`TutorState.COMPLETE`

For every other TutorState:

- run the deterministic detector;
- if no leak is detected, preserve the TutorTurn unchanged;
- if a leak is detected, replace the student-visible message with a safe fallback before persistence and response;
- set `reveal_final_answer=False`;
- preserve the application-controlled TutorState;
- preserve hint level, skill tags, likely_correct, misconception, and other TutorTurn metadata unless directly required for safety.

Do not introduce a new state transition.

## Required start behavior

After `ai.first_turn(...)` returns and before the assistant message is persisted:

1. Use `analysis.expected_answer`.
2. Use `tutor_turn.message`.
3. Use `tutor_turn.reveal_final_answer`.
4. Run the deterministic detector unless the resulting state is COMPLETE.
5. If guarded, replace only the unsafe student-facing portions required by this task.
6. Persist the guarded message.
7. Return the guarded TutorTurn.

The original internal ProblemAnalysis must remain unchanged.

## Required reply behavior

After `ai.continue_turn(...)` returns and before session state/message persistence:

1. Use `session.internal_expected_answer`.
2. Use `tutor_turn.message`.
3. Use `tutor_turn.reveal_final_answer`.
4. Run the deterministic detector unless the resulting state is COMPLETE.
5. If guarded, persist and return the guarded TutorTurn.
6. Do not persist the leaking assistant message.

## Safe fallback

Use one concise Socratic fallback that does not contain the expected answer.

It should ask the student to continue reasoning or verify their work without giving the final answer.

Keep the fallback deterministic.

Do not call TutorAI again to regenerate a safe response.

## COMPLETE behavior

If the resulting TutorTurn state is `TutorState.COMPLETE`:

- do not suppress the message because of the leakage detector;
- preserve the original message;
- preserve `reveal_final_answer`.

This task only defines permission at COMPLETE. It does not change how COMPLETE is reached.

## Security requirements

A guarded leak must not appear in:

- persisted TutorMessage content;
- StartTutorResponse;
- TutorReplyResponse.

The expected answer itself must remain server-internal.

## Acceptance criteria

- Both `/tutor/start` and `/tutor/reply` enforce the detector.
- Enforcement occurs before assistant-message persistence.
- Textual leak with `reveal_final_answer=False` is still blocked.
- `reveal_final_answer=True` before COMPLETE is blocked.
- Guarded turn has a safe fallback message.
- Guarded turn has `reveal_final_answer=False`.
- Guarded turn preserves its TutorState.
- Safe non-leaking turn remains unchanged.
- COMPLETE turn is allowed through unchanged.
- `/reply` uses persisted `session.internal_expected_answer`.
- `/start` uses internal `analysis.expected_answer`.
- Leaking text is never persisted when guard fires.
- Leaking text is never returned when guard fires.
- Existing state transition behavior remains unchanged.
- No schema/model/migration/TutorAI changes.
- Only the three allowed implementation files change.
- Existing backend tests remain green.
- Evaluation dataset includes at least one explicit early-turn answer-leakage case using the existing `first_turn_must_not_contain` schema.
- No new eval schema or eval infrastructure is introduced.

## Required tests

- `/reply`: persisted `internal_expected_answer` is used to detect and block leakage.
- `/reply`: leaking assistant text is not persisted.
- guarded turn keeps the same TutorState and sets `reveal_final_answer=False`.
- safe non-leaking output is unchanged.
- COMPLETE output containing the expected answer is allowed unchanged.
