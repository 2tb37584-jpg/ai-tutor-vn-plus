# M05-16 — Add Authored-Session Deterministic Verification Adapter

Status: DONE
Codex: YES — SMALL
Module: Tutor Engine

## Goal

Make non-transfer tutor attempts use the trusted authored question-bank verifier whenever the session has:

```text
authored_question_id
```

The verification authority must be:

```text
session.authored_question_id
→ get_question(...)
→ verification_request_for_candidate(...)
```

and must not fall back to generic session fields or model correctness when authored provenance exists but cannot be resolved.

This task does not add the authored-start endpoint.

## Context

M05-15 persisted:

```text
TutorSession.authored_question_id
```

The current non-transfer runtime uses:

```python
_verification_request_for_session(session, candidate)
```

which currently derives deterministic verification only from:

```text
session.verification_family
session.internal_expected_answer
session.normalized_problem
```

and supports the narrow runtime families:

```text
numeric
expression_equivalence
linear_equation
```

The question bank already has the trusted authored adapter:

```python
verification_request_for_candidate(item, candidate)
```

supporting authored deterministic families including:

```text
numeric
expression_equivalence
linear_equation
factorization
domain_condition
```

Transfer verification already resolves a persisted question ID server-side and uses this adapter.

M05-16 extends the same trust principle to the original authored question used to start a session.

## Core invariant

The routing rule for non-transfer verification becomes:

```text
if session.authored_question_id is not None:
    resolve authored item
    use authored-item verification adapter
    if authored resolution/build fails:
        fail closed
        DO NOT fall back to generic session verification
else:
    preserve existing free-form session verification behavior
```

Presence of authored provenance changes the source of verification authority.

## Implementation contract

### 1. Add an authored verification helper

Add a narrow helper in `backend/app/api/tutor.py`, adjacent to the existing verification helpers.

Suggested shape:

```python
def _authored_verification_request_for_session(
    session: TutorSession,
    candidate: str,
) -> VerificationRequest | None:
    authored_question_id = session.authored_question_id
    if authored_question_id is None:
        return None

    item = get_question(authored_question_id)
    if item is None:
        return None

    if session.primary_skill and item.skill_code != session.primary_skill:
        return None

    try:
        return verification_request_for_candidate(item, candidate)
    except ValueError:
        return None
```

Unexpected programmer/runtime exceptions such as `TypeError` must continue to propagate rather than being silently swallowed.

### 2. Route authored sessions before generic session verification

At the top of:

```python
_verification_request_for_session(...)
```

use:

```text
if session.authored_question_id is not None:
    return authored verification result
```

This ordering is mandatory.

An authored session with an invalid/missing/unsupported authored item must return:

```text
None
```

from `_verification_request_for_session(...)`.

It must not continue into:

```text
session.verification_family
session.internal_expected_answer
session.normalized_problem
```

as fallback authority.

### 3. Preserve free-form behavior exactly

When:

```text
session.authored_question_id is None
```

the existing generic verification behavior remains unchanged.

Existing supported free-form families remain:

```text
numeric
expression_equivalence
linear_equation
```

Do not broaden free-form runtime support to factorization/domain in this task.

### 4. Use actual deterministic request family for evidence metadata

The non-transfer runtime currently has access to:

```python
verification_request.family.value
```

after a deterministic request is built.

For verification telemetry/mastery evidence generated from that request, use the actual request family as the authoritative `verification_method`.

Do not use stale or mismatched:

```text
session.verification_family
```

when an actual deterministic request already exists.

Required value:

```python
verification_request.family.value
```

This must remain behaviorally equivalent for valid free-form sessions and become correct for authored sessions.

Do not modify transfer mastery evidence in this task; it already derives method from the transfer verification request.

## Fail-closed rules

When `authored_question_id` is present:

### Unknown question ID

```text
get_question(...) -> None
```

Result:

```text
no deterministic verification request
no fallback to generic session expected answer/problem
no deterministic mastery evidence
```

### Authored skill mismatch

If:

```text
item.skill_code != session.primary_skill
```

when the session has a primary skill:

```text
fail closed
```

Do not verify under mismatched provenance.

### Unsupported/invalid authored verifier adapter

If the authored adapter raises its expected contract `ValueError`:

```text
return None
```

Do not fall back.

### Unexpected builder/programmer failure

Unexpected errors such as:

```text
TypeError
```

must propagate.

Do not hide programming defects behind an unverified/model path.

## `likely_correct` authority

M05-16 must preserve the rule:

```text
model TutorTurn.likely_correct is not deterministic verification authority
```

If authored verification cannot produce a deterministic request:

```text
likely_correct=True
```

must not create verified mastery evidence.

The generated tutor turn may still exist as conversational output under current runtime behavior, but no verified mastery event may be fabricated from it.

## Transfer isolation

When:

```text
current_state is TRANSFER
```

the existing:

```python
_transfer_verification_request_for_session(...)
```

path remains authoritative.

`authored_question_id` identifies the original question that started the session.

`transfer_question_id` identifies the later transfer item.

Do not let the original authored question replace transfer verification while in `TRANSFER`.
