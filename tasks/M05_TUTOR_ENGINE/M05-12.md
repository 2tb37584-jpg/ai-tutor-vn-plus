# M05-12 — Wire Deterministic TRANSFER Verification and Completion

Status: ACTIVE
Codex: YES
Module: Tutor Engine

## Goal

Wire deterministic transfer-answer verification into `tutor_reply(...)` so that a learner in `TutorState.TRANSFER` reaches `COMPLETE` only when the persisted authored transfer item verifies as deterministically correct.

This task must reuse the existing transfer verification adapter and the existing state-machine transition:

```text
TRANSFER + TRANSFER_COMPLETED -> COMPLETE
```

It must not update mastery, invoke the recommender, or use model `likely_correct` for transfer correctness.

## Context

Completed prerequisites:

- M05-09 persists `TutorSession.transfer_question_id`.
- M05-10 reconstructs the exact authored transfer item and builds the family-specific deterministic `VerificationRequest`.
- M05-11 deterministically selects and persists an authored same-skill transfer item when the session enters `TRANSFER`.
- The state machine already supports:
  ```text
  TRANSFER + TRANSFER_COMPLETED -> COMPLETE
  ```

Current blocker:

```text
tutor_reply(...)
```

has no dedicated deterministic verification branch for:

```text
current_state == TRANSFER
```

As a result, `TRANSFER_COMPLETED` is never emitted by runtime.

## Micro-task

Add the smallest explicit runtime branch:

```text
if current_state == TRANSFER:
    build transfer VerificationRequest from persisted transfer_question_id
    run deterministic verify(...)
    ignore likely_correct
    if status == CORRECT:
        transition with TRANSFER_COMPLETED
    else:
        remain TRANSFER
```

Do not change tutor-state definitions.

Do not assign `COMPLETE` directly.

Do not update mastery in this task.

## Runtime contract

When:

```text
current_state == TutorState.TRANSFER
```

the runtime must use:

```python
_transfer_verification_request_for_session(
    session,
    payload.student_message,
)
```

Do not use:

```python

```

for transfer correctness.

Do not reconstruct trusted transfer context from original-session fields.

## Verification outcomes

### Deterministic CORRECT

If a transfer verification request exists and:

```text
verify(request).status == CORRECT
```

then emit:

```text
TutorEvent.TRANSFER_COMPLETED
```

through the existing state transition function.

Expected next state:

```text
COMPLETE
```

Do not directly assign `COMPLETE`.

### Deterministic INCORRECT

If:

```text
verify(request).status == INCORRECT
```

remain in:

```text
TRANSFER
```

Do not let `likely_correct=True` override this result.

### UNSUPPORTED

If:

```text
verify(request).status == UNSUPPORTED
```

remain in:

```text
TRANSFER
```

Do not complete.

### INDETERMINATE

If:

```text
verify(request).status == INDETERMINATE
```

remain in:

```text
TRANSFER
```

Do not complete.

### Missing transfer verification request

If:

```text
_transfer_verification_request_for_session(...) is None
```

remain in:

```text
TRANSFER
```

Do not fall back to:

```text
likely_correct
original-session verifier
skill-only lookup
model judgment
```

## Model-output boundary

The model may still produce pedagogical response text for the turn according to the existing architecture.

However, model output must not decide transfer correctness.

Specifically:

```text
likely_correct=True
```

must not complete a transfer turn unless deterministic verification returned `CORRECT`.

Likewise:

```text
likely_correct=False
```

must not block completion when deterministic verification returned `CORRECT`.

Deterministic verification is authoritative for transfer completion.

## State persistence contract

After the transfer runtime branch:

- persisted `session.current_state` must equal the authoritative state-machine result;
- returned API state must agree with persisted state;
- `TRANSFER_COMPLETED` must be the event causing `COMPLETE`;
- no direct `COMPLETE` assignment is allowed.

Existing `VERIFY -> TRANSFER` behavior and M05-11 transfer-item persistence must remain unchanged.

## No mastery/recommender contract

M05-12 stops at runtime state completion.

Do not:

```text

```

as a new consequence of transfer completion.

Transfer-specific mastery evidence will be a separate task.

Post-completion recommendation will remain separate.
