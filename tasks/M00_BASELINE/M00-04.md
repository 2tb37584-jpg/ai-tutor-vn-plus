# M00-04 — Adopt Existing Dev Database Into Alembic Baseline

Status: DONE
Codex: NO

## Goal

Safely adopt the existing development `aitutor` PostgreSQL database into the Alembic baseline without recreating or dropping application tables.

## Context

The existing development database was created by SQLAlchemy `Base.metadata.create_all()` before Alembic existed.

Migration `0001_initial_schema` now represents the current seven-table application schema.

The existing database must not receive `alembic upgrade head` until it has been verified and stamped at the baseline revision.

## Scope

Operational verification only.

No application code changes.

## Requirements

1. Verify the existing `aitutor` schema matches current SQLAlchemy metadata / Alembic baseline.
2. Verification must not modify application tables or data.
3. If schema matches, stamp the existing DB at revision `0001_initial_schema`.
4. Do not run baseline upgrade DDL against the existing database.
5. Verify `alembic current` reports `0001_initial_schema (head)` afterward.
6. Existing application data must remain intact.

## Forbidden

- Do not drop or recreate `aitutor`.
- Do not delete the postgres Docker volume.
- Do not run `alembic upgrade head` against the unstamped existing `aitutor` database.
- Do not modify models.
- Do not modify migrations.
- Do not modify application code.
- Do not modify Docker Compose.

## Acceptance criteria

- Schema-drift check passes before stamping.
- Existing database is stamped at `0001_initial_schema`.
- No application table is recreated or dropped.
- Existing row counts/data remain intact.
- `alembic current` reports the baseline head.
- Backend regression tests still pass.
