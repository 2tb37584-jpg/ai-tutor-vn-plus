# M00-08 — Fix Alembic Revision-ID Startup Blocker

Status: DONE
Codex: YES
Module: Baseline / Alembic

## Goal

Restore normal backend startup by making Alembic revision `0005` compatible with the default `alembic_version.version_num VARCHAR(32)` column.

## Context

Backend startup runs:

```text

alembic upgrade head

→ uvicorn

```

The current Alembic head is:

```text

0005_tutor_session_verification_family

```

Revision chain:

```text

0003_internal_expected_answer

→ 0004_tutor_message_reply_latency

→ 0005_tutor_session_verification_family

```

`0005_tutor_session_verification_family` is longer than 32 characters.

During backend startup, PostgreSQL rejects Alembic's version-table update:

```text

sqlalchemy.exc.DataError:

(psycopg.errors.StringDataRightTruncation)

value too long for type character varying(32)

UPDATE alembic_version

SET version_num='0005_tutor_session_verification_family'

WHERE alembic_version.version_num='0004_tutor_message_reply_latency'

```

The migration itself is the current single Alembic head and has no downstream migration depending on its revision identifier.

The backend therefore exits before Uvicorn starts.

This blocker was discovered while closing M08-05. M08-05 itself is DONE and must not be reopened or modified.

## Micro-task

Shorten only the Alembic revision identifier for migration `0005` so that it fits within 32 characters.

Preferred identifier:

```text

0005_tutor_verifier_family

```

Keep:

```text

down_revision = "0004_tutor_message_reply_latency"

```

Do not change the migration's schema operations.
