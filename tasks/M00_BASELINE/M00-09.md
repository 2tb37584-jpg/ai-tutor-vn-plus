# M00-09 — Fix Backend CI Editable-Install Packaging

Status: ACTIVE
Codex: YES
Module: Baseline

## Goal

Create an explicit setuptools package-discovery configuration so editable installation discovers the `app` package tree only and does not treat `alembic` as a top-level application package.

## Context

Current GitHub CI backend job runs:

```text
pip install -e '.[dev]'
```

from:

```text
backend
```

It fails before pytest with:

```text
Multiple top-level packages discovered in a flat-layout: ['app', 'alembic']
```

Current backend layout includes:

- `backend/app/__init__.py`
- `backend/alembic/`
- `backend/pyproject.toml`

`app` is the application package tree. `alembic` is migration infrastructure and must not be accidentally discovered as an application Python package.

This is a measured CI/workflow blocker discovered during PR #2.

## Micro-task

Explicitly configure setuptools package discovery in `backend/pyproject.toml` so editable installation discovers the `app` package tree only and does not treat `alembic` as a top-level application package.

No CI workflow change is allowed unless this alone provably cannot fix the measured failure.

## Why now

All current Pull Requests receive a red overall GitHub Actions result because the backend CI job cannot install the backend package. This weakens the PR review gate and hides real backend regressions behind an infrastructure failure.

## Core-loop impact

No direct tutoring behavior change. This repairs the deterministic CI gate used to protect all core-loop changes.

## Roadmap / workflow relevance

This is allowed by the workflow task-eligibility rule because it fixes a measured blocker in the repository validation pipeline. It should be completed before opening a new product feature family.

## Planned implementation

Use explicit setuptools package discovery in `backend/pyproject.toml`.

Required semantic result:

- package discovery includes `app` and its Python subpackages;
- `alembic` is not discovered as an installable application package;
- existing project metadata/dependencies remain unchanged.

Prefer the smallest setuptools configuration that expresses:

```text
include app package tree only
```

Do not add unrelated packaging configuration.
