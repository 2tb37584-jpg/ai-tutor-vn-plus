# M00-03 — Establish Alembic Migration Baseline

Status: DONE
Codex: YES — SMALL

## Goal

Establish Alembic as the backend schema migration mechanism and create an initial migration representing the current SQLAlchemy schema.

This task must NOT change application schema or runtime startup behavior.

## Context

The backend currently uses `Base.metadata.create_all(bind=engine)` as developer convenience.

The existing PostgreSQL database is persistent through the Docker `postgres_data` volume.

`create_all()` can create missing tables but cannot migrate an existing table when new columns are introduced.

Future tutor-state persistence will require safe schema evolution.

## Allowed implementation files

- backend/pyproject.toml
- backend/alembic.ini
- backend/alembic/env.py
- backend/alembic/script.py.mako
- backend/alembic/versions/0001_initial_schema.py

## Forbidden scope

Do NOT modify:

- backend/app/main.py
- backend/app/models/**
- backend/app/db/**
- backend/app/api/**
- backend/app/services/**
- backend/app/schemas/**
- frontend/**
- docker-compose.yml
- existing database data
- tutor behavior
- task/status files during Codex implementation

Do not add any dependency other than Alembic.

## Requirements

1. Add Alembic as a backend dependency compatible with SQLAlchemy 2.x.

2. Configure Alembic to use the same database URL as the application.

3. Alembic metadata must come from the existing SQLAlchemy `Base.metadata`.

4. Ensure all models are imported before metadata is used.

5. Create an initial migration for the current schema only.

Current application tables:

- users
- students
- skills
- mastery
- tutor_sessions
- tutor_messages
- attempts

6. Preserve existing foreign keys, indexes, uniqueness constraints and column nullability.

7. The migration must have a working downgrade that removes the baseline schema in dependency-safe reverse order.

8. Do NOT run the initial migration against the existing populated `aitutor` database.

9. Do NOT remove or modify `Base.metadata.create_all()` in this task.

## Acceptance criteria

- `alembic` is installed after rebuilding the backend image.
- `alembic heads` reports one head.
- A brand-new disposable PostgreSQL database upgrades from empty to head successfully.
- The disposable database contains exactly the expected seven application tables plus `alembic_version`.
- `alembic current` reports the baseline revision.
- `alembic downgrade base` succeeds on the disposable database.
- Existing `aitutor` database is not modified by migration testing.
- Existing backend tests still pass.
- Only allowed implementation files are changed.

## Tests

Rebuild backend after dependency change.

Run the existing backend test suite.

Run Alembic against a disposable PostgreSQL database, never the existing `aitutor` database.

## Stop conditions

Stop and report instead of expanding scope if:

- matching the current schema requires modifying SQLAlchemy models;
- existing DB data must be changed;
- `main.py` must be changed;
- Docker Compose must be changed;
- another dependency besides Alembic is needed;
- migration behavior cannot be tested without touching the existing `aitutor` database.
