# M00-05 — Switch Runtime Schema Workflow to Alembic

Status: ACTIVE
Codex: YES — SMALL

## Goal

Make Alembic the runtime schema upgrade mechanism and remove SQLAlchemy `create_all()` from FastAPI startup.

The backend container must apply pending Alembic migrations before starting Uvicorn.

## Prerequisites

- M00-03 DONE — Alembic baseline exists.
- M00-04 DONE — existing development database is stamped at `0001_initial_schema`.

## Current state

`backend/app/main.py` currently calls:

`Base.metadata.create_all(bind=engine)`

during FastAPI startup.

The backend Docker image currently starts Uvicorn directly.

## Intended design

Schema migration must happen before application startup.

FastAPI must not create or alter database tables.

The container startup flow should be:

`alembic upgrade head` → `uvicorn`

## Allowed implementation files

Exact implementation scope will be:

- backend/app/main.py
- backend/Dockerfile

No additional file should be needed unless implementation proves otherwise.

## Forbidden scope

Do NOT modify:

- SQLAlchemy models
- Alembic revisions
- alembic/env.py
- database data
- docker-compose.yml
- API routes
- tutor services
- frontend
- dependencies
- task/status files during Codex implementation

Do not add a dependency.

## Requirements

1. Remove `Base.metadata.create_all()` from FastAPI startup.
2. Remove imports that become unused after removing `create_all()`.
3. Backend container startup must run `alembic upgrade head` before Uvicorn.
4. Uvicorn must not start if migration fails.
5. Preserve the existing Uvicorn development behavior:
   - host `0.0.0.0`
   - port `8000`
   - reload enabled.
6. Do not run migration commands from application request/startup code.
7. Do not change application schema in this task.

## Acceptance criteria

- `backend/app/main.py` contains no `create_all()` startup behavior.
- Backend container starts successfully against the existing stamped `aitutor` database.
- Startup runs `alembic upgrade head` before Uvicorn.
- `GET /health` still returns HTTP 200.
- `alembic current` remains at head.
- `alembic check` reports no new upgrade operations.
- Existing backend regression tests pass.
- Existing application data remains intact.
- Only the approved implementation files change.

## Tests

After implementation:

1. Rebuild backend image.
2. Restart backend against the existing stamped development database.
3. Verify backend startup logs show Alembic before Uvicorn.
4. Verify `/health`.
5. Run `alembic current`.
6. Run `alembic check`.
7. Run full backend pytest suite.
8. Verify Git scope.

## Stop conditions

Stop and report instead of expanding scope if:

- Docker Compose must change;
- models or migration revisions must change;
- another dependency is required;
- application schema must change;
- more than the two approved implementation files are required.
