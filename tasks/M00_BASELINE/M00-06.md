# M00-06 — Developer Workflow Automation

Status: READY
Codex: YES

## Goal

Implement the first real developer-command layer promised by `09_DEV_WORKFLOW.md` so repetitive repository checks and test commands can be run through one short PowerShell entry point.

The task must reduce manual command sequences without weakening any existing quality gate.

## Context

The project currently follows the intended engineering discipline, but many steps are still executed manually:

- checking Git status / HEAD;
- checking Docker service state;
- running targeted eval tests;
- running the full backend test suite;
- running diff/status review commands;
- preparing a short repository snapshot for ChatGPT.

`09_DEV_WORKFLOW.md` already defines the intended interface, but the automation has not yet been implemented.

M00-06 implements that interface.

Task lifecycle synchronization (`task status/start/done`) is explicitly out of scope and should be handled by M00-07.

## Module / micro-task

Module:

`M00 Baseline & development discipline`

Micro-task:

Create one PowerShell developer entry point with a small command dispatcher and safe output.

Required commands:

```powershell
.\dev.ps1 status
.\dev.ps1 review
.\dev.ps1 test eval
.\dev.ps1 test full
.\dev.ps1 snapshot
```

## Allowed files

Default allowed files:

1. `dev.ps1`
2. `09_DEV_WORKFLOW.md`
3. one small test/validation script only if truly necessary
4. one short usage section in an existing developer README only if needed

Prefer 2–3 files.

If implementation requires broader repo changes, stop and split the task.

## Forbidden scope

Do NOT modify:

- production business logic;
- TutorAI prompts;
- eval scorer semantics;
- taxonomy;
- eval fixtures;
- API schemas;
- database migrations;
- frontend behavior;
- provider configuration;
- dependencies;
- task lifecycle/status automation.

Do not add a new dependency unless there is a documented, compelling reason.

Do not call live paid-model eval from any default command.

Do not print API keys, `.env` contents, or student data.

## Command contract

### `status`

Must show, at minimum:

- current Git short SHA;
- working-tree summary;
- ACTIVE task if deterministically discoverable from `TASK_INDEX.md`;
- basic `docker compose ps` status when Docker is available.

Must degrade gracefully when Docker is unavailable.

Must not print secrets.

### `review`

Must run and report:

```text
git diff --check
git diff --stat
git status --short
```

Output should be concise and copy/paste friendly.

Nonzero `git diff --check` must produce a nonzero exit code.

### `test eval`

Must run the deterministic targeted eval-related test command used by the repository.

Default behavior must not call a live provider.

If no stable single eval-test target exists, use the smallest deterministic existing eval test suite and document the exact command.

### `test full`

Must run the full backend deterministic test suite through the repository's existing Docker Compose environment.

Expected shape:

```text
docker compose exec backend pytest -q
```

Do not add live model calls.

### `snapshot`

Must print a short, safe project snapshot containing at least:

```text
HEAD: <sha>
ACTIVE: <task or none/unknown>
Git: <clean or changed>
Backend/Docker: <available status summary>
Eval corpus: <case count if cheaply discoverable>
Provider API mode: <non-secret metadata only if safely available>
```

Must never print the API key.

Snapshot should be intentionally short enough to paste into ChatGPT.

## Safety requirements

The script must:

- never echo `.env`;
- never output `OPENAI_API_KEY`;
- never dump environment variables wholesale;
- never write secrets to snapshot files;
- avoid student PII;
- avoid modifying repository files for read-only commands;
- fail clearly when required tooling is unavailable.

## UX requirements

- PowerShell-native invocation;
- clear usage message for invalid commands;
- meaningful nonzero exit codes on failures;
- no interactive prompts for normal commands;
- commands should work from repository root;
- output should use stable headings so ChatGPT can parse it easily.

## Tests / validation

At minimum validate:

```powershell
.\dev.ps1 status
.\dev.ps1 review
.\dev.ps1 test eval
.\dev.ps1 test full
.\dev.ps1 snapshot
```

Also validate:

```powershell
.\dev.ps1 invalid-command
```

Expected:

- usage/help is printed;
- exit code is nonzero;
- repository remains unchanged.

Run:

```powershell
git diff --check
git status --short
git --no-pager diff --stat
```

No live provider call is required for M00-06.

## Acceptance criteria

M00-06 is DONE when:

- `dev.ps1` exists in Git;
- `status`, `review`, `test eval`, `test full`, and `snapshot` all work;
- deterministic eval tests can be launched with one command;
- full backend tests can be launched with one command;
- review output replaces the repeated manual diff/status sequence;
- snapshot contains useful context but no secret;
- Docker-unavailable behavior is understandable and does not crash with an opaque error;
- invalid commands return usage + nonzero exit code;
- no new dependency is added;
- no product/business behavior changes;
- `git diff --check` passes;
- full backend tests pass.
