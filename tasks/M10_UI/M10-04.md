# M10-04 — Start Recommended Authored Question from UI

Status: ACTIVE
Codex: YES — SMALL
Module: UI

## Goal

Allow the learner to explicitly start the currently recommended authored question from the existing `next_learning_action` UI.

The client sends only trusted identity:

`student_id + question_id`

to:

`POST /tutor/start-authored`

No automatic start is allowed.

## Why now

M10-03 already renders the learner-safe recommendation but it is informational only.

M05-17 now provides the trusted server-side authored-start endpoint.

This task closes the current adaptive-learning integration seam:

`completion → recommendation → learner chooses → trusted authored session starts`

without creating a new subsystem.

## Core-loop impact

Directly closes integration debt in the adaptive learning loop by allowing a completed recommendation to become the next real tutoring session.

## Why not defer

The recommendation system is already delivered to the UI, but the learner cannot act on it through the trusted authored-question path. Leaving it informational keeps the core loop incomplete.

## Exit criterion affected

The adaptive-learning flow must be connected end-to-end using trusted question identity rather than client-owned problem text.

## Planned implementation requirements

1. Add a frontend response type matching the existing learner-safe authored-start response:
   * `session_id`
   * `question: NextLearningAction`
   * `tutor: TutorTurn`
2. Add an explicit learner action such as `Bắt đầu bài này` inside the existing `nextLearningAction` section.
3. Call `POST /tutor/start-authored`.
4. Send exactly `student_id` and `question_id`.
5. Take `question_id` from the current recommendation.
6. Do not send recommendation metadata as authority.
7. Do not start automatically when recommendation arrives.
8. Do not clear the current recommendation/session before the request succeeds.
9. On failure, keep the current session and recommendation visible and allow retry.
10. On success, replace the session ID and chat, clear the consumed recommendation and stale reply, clear stale free-form presentation state, and retain the server-returned authored problem.
11. Keep any authored presentation state local to `page.tsx`.
12. Normal free-form start, `Bài mới`, and logout must clear authored presentation state.
13. Preserve reply, hint, and mastery behavior.

The authored recommendation must be started for the student who owns the current tutor session, not whichever sidebar student happens to be selected later.

## Deterministic review cases

1. Recommendation exists: button is visible and no request occurs before click.
2. Click sends `/tutor/start-authored` with only `student_id` and recommended `question_id`.
3. Successful start installs the new session, first tutor turn, and server-returned problem while clearing the recommendation.
4. Failed start preserves the previous session and recommendation for retry.
5. `Bài mới` clears authored presentation state.
6. Successful free-form start clears stale authored presentation state.
7. Student A completes a session, the sidebar changes to student B, and `Bắt đầu bài này` still sends student A's session identity.
