# M10-03 — Render Post-Completion Next Learning Action

Status: DONE
Codex: YES — SMALL
Module: UI

## Goal

Render the backend-provided `next_learning_action` after a tutor session completes.

This task is presentation-only.

Do not automatically start a new tutor session.

## Context

```text
next_learning_action:
  question_id
  skill_code
  problem_text
  difficulty
```

The backend only returns this payload on the trusted deterministic:




The current UI already renders:

## Frontend contract

Add a local type matching the learner-safe backend payload:

```ts
type NextLearningAction = {
  question_id: string;
  skill_code: string;
  problem_text: string;
  difficulty: number;
};
```

Extend:

```ts
type TutorReplyResponse = {
  tutor: TutorTurn;
  next_learning_action: NextLearningAction | null;
};
```

If the client API helper can receive an omitted optional field, a compatible optional/null type is acceptable:

```ts
next_learning_action?: NextLearningAction | null;
```

Prefer matching the actual backend response contract without introducing a wider abstraction.

## State ownership

Store the latest recommended next-learning action separately from chat messages.

Suggested state:

```ts
const [nextLearningAction, setNextLearningAction] =
  useState<NextLearningAction | null>(null);
```

On successful `/tutor/reply`:

```text
setNextLearningAction(data.next_learning_action ?? null)
```

This ensures:

- a completion recommendation is displayed;
- later responses without a recommendation clear stale UI if such a response is ever possible;
- recommendation metadata is not embedded into chat-message history.

## Reset behavior

Clear `nextLearningAction` when:

1. a new tutor session starts successfully;
2. the user clicks the existing "Bài mới" reset action;
3. logout/reset behavior clears the current tutor context, if that logic already resets the session in this file.

Do not create new lifecycle behavior beyond clearing local presentation state.

## Rendering behavior

Render only when:

```ts
nextLearningAction !== null
```

Place it near the completion/session area, after the chat or near tutor actions.

Use existing CSS classes/components where practical.

Do not add a CSS file merely for this task.

Suggested content:

```text

<problem_text>
```

Do not render or infer any expected answer or verifier metadata.
