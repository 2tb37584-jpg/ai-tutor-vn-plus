# M08-09 — Deliver Next Learning Action on Tutor Completion

Status: DONE
Codex: YES — SMALL
Module: Mastery / Adaptive Learning

## Goal

Wire the internal M08-07 next-learning-action seam into the tutor completion response.

When the current `/tutor/reply` request transitions the session into `TutorState.COMPLETE`, return an optional learner-safe next-learning-action payload.

Do not start a new tutor session in this task.

## Context

M08-07 is DONE and provides:

```python
recommend_next_learning_question(
    db,
    *,
    student_id,
    tutor_state,
    now,
) -> QuestionBankItem | None
```

The seam:

- gates recommendation on `TutorState.COMPLETE`;
- flushes same-transaction mastery changes before reading;
- loads the student's current mastery rows;
- maps them to `MasterySnapshot`;
- forwards caller-injected `now`;
- calls the pure deterministic recommender;
- returns `QuestionBankItem | None`;
- converts only the exact no-eligible condition into `None`;
- does not commit.

M08-08 is DONE and defines the delivery contract:

```text
TRANSFER
+ deterministic CORRECT
→ TRANSFER_COMPLETED
→ COMPLETE
→ call M08-07 once
→ project learner-safe fields
→ commit existing tutor transaction
→ return TutorReplyResponse
```

The current public response is:

```python
class TutorReplyResponse(BaseModel):
    tutor: TutorTurn
```

The current frontend consumes only `data.tutor`.

M08-09 adds the backend delivery field only.

## Micro-task

Add a learner-safe optional next-learning-action projection to `TutorReplyResponse`.

Call the M08-07 seam only when the current request transitions into `COMPLETE`.

Trigger condition must be based on the state transition in the current request, conceptually:

```python
current_state is not TutorState.COMPLETE
and tutor_turn.state is TutorState.COMPLETE
```

Do not call recommendation merely because a loaded session is already complete.

Add a dedicated response model, for example:


```python
class TutorReplyResponse(BaseModel):
```

Equivalent naming is acceptable if the contract remains equally narrow.

## Learner-safe projection

When M08-07 returns a `QuestionBankItem`, project only:

```text
question_id <- item.id
skill_code <- item.skill_code
problem_text <- item.problem_text
difficulty <- item.difficulty
```

Do not expose or serialize:

```text
expected_answer
verification_reference
verification_family
internal verifier metadata
```

Do not serialize the internal `QuestionBankItem` object directly.

## Trigger contract

Recommendation runs only on the transition into `COMPLETE` during the current reply.

Expected current path:

```text
current_state = TRANSFER
deterministic transfer verification = CORRECT
→ tutor_turn.state = COMPLETE
→ call recommend_next_learning_question(...)
```

Do not invoke it on:

```text
ASK_ATTEMPT
HINT_1
HINT_2
EXPLAIN_STEP
VERIFY
entry into TRANSFER
ordinary mastery updates
already-COMPLETE session state
```

The recommendation seam must be called exactly once for the completion request.

## Clock ownership

Use the tutor route's existing application clock seam.

Create one deterministic route-owned `now` value for the recommendation operation and pass it unchanged to M08-07.

Prefer reusing the existing `_utcnow()` seam rather than calling `datetime.now()` directly in new recommendation code.

Do not modify M08-07 clock behavior.

## Transaction ordering

Preserve this logical order:

```text
1. deterministic transfer verification
2. transfer mastery evidence recording
3. authoritative state becomes COMPLETE
4. call M08-07
5. project optional public next-learning-action payload
6. persist assistant message / session state
7. existing db.commit()
8. return TutorReplyResponse
```

M08-07 owns its internal flush before mastery read.

Do not add another commit.

Do not move recommendation ahead of transfer mastery evidence.

## No-eligible behavior

If M08-07 returns:

```python

```

return:

```python
TutorReplyResponse(
    tutor=tutor_turn,
    next_learning_action=None,
)
```

The tutor reply must still succeed.

Do not convert this into an HTTP error.

## Risks

### Duplicate recommendation

Do not use:

```python
if tutor_turn.state is TutorState.COMPLETE:
```

alone.

A session already complete in a later/future request must not trigger recomputation.

Use transition-aware gating based on both current state and resulting state.

### Answer leakage

Never pass the internal `QuestionBankItem` directly into Pydantic response serialization.

Build an explicit learner-safe projection.

### Transaction ordering

Recommendation must see the transfer mastery evidence from the same completion transaction.

Do not call the recommendation seam before `record_mastery_evidence(...)`.

### Scope expansion

Do not combine this task with:

```text
frontend rendering

recommendation persistence/history
new endpoints
```

Those are separate tasks.
