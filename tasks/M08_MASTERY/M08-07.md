# M08-07 — Add Internal Next-Learning-Action Recommendation Seam

Status: DONE
Codex: YES — SMALL
Module: Mastery / Adaptive Learning

## Goal

Add the smallest internal application/service seam that can select the next learning question after a tutor session is complete.

The seam must:

- gate recommendation on `TutorState.COMPLETE`;
- load the student's current persisted mastery rows;
- map them exactly to `MasterySnapshot`;
- inject a caller-supplied deterministic `now`;
- call the existing pure `recommend_next_question(...)`;
- return `QuestionBankItem | None`;
- translate only the existing "no eligible question-bank skills" condition into `None`.

Do not wire this into a public API or frontend in this task.

## Why this task

M08-05 already provides the pure deterministic recommender.

M08-06 defined the integration contract and explicitly separated:

```text
Task A — make TRANSFER -> COMPLETE explicit
Task B — integrate next learning recommendation after COMPLETE
```

Task A is now complete through M05-09 through M05-13 and M05-07 closure.

Repository inspection after M05-07 confirmed:

- `recommend_next_question(...)` has no runtime caller;
- no existing application consumer for the returned `QuestionBankItem` exists;
- `TutorReplyResponse` has no next-question payload;
- M08-06 forbids speculative public API/schema expansion.

Therefore this task creates a meaningful reusable internal seam instead of adding a fire-and-forget call in `tutor.py`.

## Micro-task

Create one small service that converts current ORM mastery state into the existing pure recommender input and returns the recommended authored question.

Suggested contract:

```python
def recommend_next_learning_question(
    db: Session,
    *,
    student_id: int,
    tutor_state: TutorState,
    now: datetime,
) -> QuestionBankItem | None:
    ...
```

Equivalent naming is acceptable if the contract remains equally narrow.

Behavior:

```text
tutor_state != COMPLETE
→ return None
→ do not query mastery
→ do not call recommender

tutor_state == COMPLETE
→ flush pending same-transaction ORM changes if required
→ load Mastery rows for student_id
→ map every row exactly to MasterySnapshot
→ call recommend_next_question(..., now=caller_now)
→ return selected QuestionBankItem
```

If the recommender raises exactly:

```text
ValueError("no eligible question-bank skills")
```

translate it to:

```text
None
```

Any other `ValueError` must propagate.

Do not silently swallow invalid mastery/recommender inputs.

## Required behavior

1. Non-`COMPLETE` state returns `None`.
2. Non-`COMPLETE` state does not call the recommender.
3. Non-`COMPLETE` state does not perform an unnecessary mastery query.
4. `COMPLETE` state loads only mastery rows for the requested student.
5. Each ORM row maps exactly to:

```python
MasterySnapshot(
    skill_code=row.skill_code,
    probability=row.probability,
    exposures=row.exposures,
    last_seen_at=row.last_seen_at,
)
```

6. Caller-provided `now` is forwarded unchanged.
7. The returned `QuestionBankItem` is returned unchanged.
8. The no-eligible condition becomes `None`.
9. Other `ValueError` failures propagate.
10. No commit occurs inside the seam.
11. Pending same-transaction mastery changes are visible before recommendation. Prefer an explicit `flush()` before the mastery read if needed by the existing DB contract.
12. No DB access is introduced into `question_recommender.py`.
