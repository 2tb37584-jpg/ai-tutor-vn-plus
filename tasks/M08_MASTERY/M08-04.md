# M08-04 — Add Pure Spaced-Review Scheduling Policy

Status: READY
Codex: YES
Module: M08 Mastery
Phase: Phase 3 — Adaptive Learning

## Direction gate

Roadmap link: Phase 3 — Spaced repetition scheduler
Core-loop impact: Mastery state -> review timing -> future next-best-question recommendation
Why now: Question bank difficulty exists, and mastery already records probability/exposures/last_seen_at, but the system has no explicit review timing policy.
Why not defer: Next-best-question selection needs to know whether a skill is due for review before combining prerequisite, mastery, and question difficulty signals.
Exit criterion affected: creates a deterministic, testable scheduling seam for adaptive practice without adding persistence or pretending the heuristic is calibrated.

## Goal

Add a pure, deterministic v1 review scheduling policy derived from existing mastery state.

Do not persist `next_review_at`.
Do not add API routes.
Do not modify mastery updates.
Do not implement recommendation ranking.
Do not implement BKT/IRT or a learned scheduler.

## Design decision

Existing mastery state already provides:

```text
probability
exposures
last_seen_at
```

For v1, review timing is derived on demand.

No duplicate scheduling state should be persisted until there is evidence that stored scheduling state is needed.

`correct_streak`, attempt history, hint count, response latency, and question difficulty are intentionally excluded from this first scheduler policy.

They may inform later calibration, but mixing them into v1 would create an unvalidated scoring model.

## Micro-task

Create a pure service module with:

```python
@dataclass(frozen=True)
class ReviewSchedule:
    due_at: datetime
    interval_days: int
    is_due: bool
    reason: str
```

and:

```python
schedule_review(
    *,
    probability: float,
    exposures: int,
    last_seen_at: datetime | None,
    now: datetime,
) -> ReviewSchedule
```

No database dependency.

## V1 policy

### Unseen / unscheduled mastery

If:

```text
exposures == 0
```

or:

```text
last_seen_at is None
```

then:

```text
interval_days = 0
due_at = now
is_due = True
reason = "unseen"
```

### Low mastery

If:

```text
0.00 <= probability < 0.50
```

then:

```text
interval_days = 1
reason = "low_mastery"
```

### Developing mastery

If:

```text
0.50 <= probability < 0.80
```

then:

```text
interval_days = 3
reason = "developing_mastery"
```

### Strong mastery

If:

```text
0.80 <= probability <= 1.00
```

then:

```text
interval_days = 7
reason = "strong_mastery"
```

For scheduled mastery:

```python
due_at = last_seen_at + timedelta(days=interval_days)
is_due = now >= due_at
```

Boundary behavior is part of the contract and must be tested exactly at:

```text
0.00
0.49
0.50
0.79
0.80
1.00
```

## Validation

Reject invalid inputs with `ValueError`.

Rules:

```text
probability must be int/float but not bool
0.0 <= probability <= 1.0
exposures must be int but not bool
exposures >= 0
last_seen_at must be datetime or None
now must be datetime
```

Datetime compatibility:

- Current persistence uses naive UTC datetimes.
- The pure policy may also support timezone-aware datetimes.
- If `last_seen_at` is not None, `last_seen_at` and `now` must both be naive or both timezone-aware.
- Mixed naive/aware inputs must raise `ValueError`.
- Do not convert timezones or silently strip timezone info.

No call to `datetime.now()` / `datetime.utcnow()` inside the policy.
`now` must always be injected by the caller so tests are deterministic.
